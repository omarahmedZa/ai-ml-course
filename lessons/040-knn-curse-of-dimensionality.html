kNN & the curse of dimensionality

You can run k-nearest-neighbours by hand, choose k, and explain why adding features can make neighbours meaningless.

FoundationsClassical ML

Why this matters— neighbours in high dimensions

k-nearest-neighbours is the most honest model in machine learning: to predict a label, find the k training points closest to the query and let them vote. No parameters are fitted, no assumption is made about the shape of the boundary, and the whole training phase is storing the data. It is the baseline every other classifier has to beat, and the idea underneath recommender systems, embedding search and retrieval-augmented generation.

The failure it prevents. A team adds 200 sensor features to a working 5-feature kNN and accuracy collapses. Nothing is broken: in 200 dimensions every point is roughly the same distance from every other, so "nearest" stops meaning "similar".

The one core idea— neighbours in high dimensions

Store every training point with its label. For a new query q, compute the distance to all of them, sort, take the k smallest, and return the majority label — or the average target for regression. That is the entire algorithm.

The knob is k. With k = 1 the prediction follows the closest single point, so one mislabelled example creates a wrong answer: low bias, high variance. With k = n every query gets the global majority: high bias, low variance. Small k draws a jagged boundary; large k draws a smooth one.

The curse is separate. Even with a perfect k, the method assumes nearby points have similar labels. As dimensions grow, the distance to the nearest point approaches the distance to the farthest, and that assumption loses its content.

ŷ = majority{ yᵢ : i ∈ k nearest to q }

k controls the bias–variance trade. Dimension controls whether "nearest" means anything.

How it actually works— neighbours in high dimensions

Part 1 — Measure, sort, vote

Distance is usually Euclidean: d(q,x) = √Σ(qⱼ − xⱼ)²(sigma, square root), summed over features j. Subtract, square, add, take the root. Scale matters enormously here, which is why features are standardised before kNN — a column measured in thousands will dominate every distance.

Why this matters: kNN cannot learn which features matter, so the norm and scaling are its assumptions.

Part 2 — Choose k by validation, not by taste

Try several values and pick the one with the lowest validation error. Use an odd k for two-class problems so votes cannot tie. A common starting point is k ≈ √n: 10 for 100 training points, 32 for 1,000. Distance-weighting — letting closer neighbours count more — often helps when the data are dense.

Why this matters: k is the only capacity dial. Too small follows noise; too large erases structure.

Part 3 — Watch the volume explode

A cube with side 1 has volume 1 whatever the dimension. To capture 10% of its points you need 10% of its volume, so each axis must cover 0.1^(1/d). At d = 2 that is 0.32; at d = 10, 0.79; at d = 100, 0.977. A "local" neighbourhood in 100 dimensions spans almost the entire range of every feature.

Distances behave the same way. A uniform point in the unit cube sits about √(d/3) from the origin: 0.82 at d = 2, 5.77 at d = 100. The spread around that average stays near 0.13 whatever the dimension, so at d = 100 distances vary by about 2%.

Part 4 — Fix it with fewer dimensions, not more data

The responses are: scale and drop features; reduce with PCA before kNN; learn a metric that pulls same-label points together; or switch to a parametric model. More rows help the estimate inside a neighbourhood, not the neighbourhood's locality.

Why this matters: doubling n in 100 dimensions barely changes the fraction of the cube your neighbours occupy.

Worked example— neighbours in high dimensions

1. Five points, three values of k

Training points: A(1,1), B(2,3), A(4,2), B(3,4), A(0,1). Query q = (2,2).

PointLabelDifferenceDistanceRank
(1,1)A(1, 1)1.4142
(2,3)B(0, 1)1.0001
(4,2)A(−2, 0)2.0003
(3,4)B(−1, −2)2.2364
(0,1)A(2, 1)2.2365

Read it as a sentence. At k = 1 the answer is B, because (2,3) is one unit away. At k = 3 the neighbours are B, A, A, so the vote is A by two to one. At k = 5 the count is A: 3, B: 2, still A. One extra neighbour flips the k = 1 answer, which is exactly the variance that larger k removes.

2. Why the third neighbour is on the fence

The circle in the figure has radius 2, and (4,2) sits at exactly 2.000. A rounding error pushing it to 2.001 would leave B, A, B and flip the prediction. Boundary cases like this are why odd k exists.

3. The same data in 100 dimensions

Add 95 noise features drawn uniformly from 0 to 1. Two independent draws differ by 1/6 = 0.17 squared on average, so 95 × 0.17 = 16 swamps the signal's 2. Every distance now sits near √18 = 4.24, and the true neighbour is indistinguishable from a random point. The vote approaches a coin flip although the first two features still separate A from B.

The trap— neighbours in high dimensions

Most common wrong mental model

"More features give kNN more information." Features only help if they vary in a way that correlates with the label and varies less than the noise. Otherwise each one adds a little distance to every pair of points and dilutes the dimensions that were doing the work.

It feels right because in two dimensions an extra feature genuinely sharpens the picture. But the geometry changes with dimension: volume grows exponentially, so the data become sparse, and distances concentrate until the nearest point is barely nearer than a random one.

Correction: judge a feature by validation error, not by whether it is informative in principle. Keep the count modest, scale and select, and reduce dimension before trusting kNN.

The tell: validation accuracy falls when you add features that should be relevant, and the distance to the 1st neighbour is nearly the distance to the 100th. A second tell is that kNN loses to logistic regression on the same table — the signal is there, but the geometry has stopped being local.

Retrieval check— neighbours in high dimensions

  1. Why is an odd k preferred for two classes, and what happens with k = 2?
    Answer

    An odd k cannot split evenly, so no tie-break rule is needed. With k = 2 one vote each is possible, and the prediction then depends on an arbitrary tie-break such as the smaller index.

  2. At d = 2 the axis fraction for 10% of a cube is 0.32. What is it at d = 4, and what does that say about locality?
    Answer

    0.1^(1/4) = 0.562. Just doubling the dimension forces the neighbourhood to cover more than half of each axis, so "local" is already weakening.

  3. Your 1-NN classifier gets 95% on training data and 61% on validation. Is the problem variance, bias, or distance concentration?
    Answer

    Most likely variance: with k = 1 each training point predicts itself perfectly, so training accuracy is meaningless. Raise k or add data; if validation stays near chance, suspect distance concentration instead.

Build it in Colab— neighbours in high dimensions

Runnable, NumPy-only: open the notebook in Colab · local copy. It computes the five distances, runs the vote for three values of k, and plots validation accuracy as noise features are added.

import numpy as np
X = np.array([[1,1],[2,3],[4,2],[3,4],[0,1]],float)
y = np.array(["A","B","A","B","A"])
q = np.array([2.,2.])
d = np.linalg.norm(X - q,axis=1)
order = np.argsort(d)
for k in (1,3,5):
    labels,counts = np.unique(y[order[:k]],return_counts=True)
    print(k,labels[counts.argmax()])
