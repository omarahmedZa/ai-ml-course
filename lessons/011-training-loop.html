The training loop

You can write the five-line loop and read a loss curve well enough to diagnose it.

Why this matters

This is the loop you will run hundreds of times in your project. Ninety percent of "my model doesn't work" is one of four mistakes inside these five lines, and all four are visible in the loss curve.

The one core idea

Training is a fixed cycle: forward → loss → backward → step → zero the gradients, repeated over shuffled batches. The learning rate is the only number that reliably decides whether it works.

How it actually works

for x, y in loader:          # one batch
    pred = model(x)          # forward
    loss = criterion(pred, y)
    loss.backward()          # gradients accumulated
    opt.step()               # w ← w − η∇w
    opt.zero_grad()          # reset, or gradients add up
TermMeaning
BatchSubset of data in one step. Size trades noise for speed.
StepOne parameter update. steps = epochs × n / batch
EpochOne pass over the whole dataset.
Learning rate ηStep size. Too high → divergence; too low → glacial.

Worked example

1. Sizing a run

10,000 training examples, batch 100 → 100 steps per epoch. Twenty epochs → 2,000 updates. At batch 1,000 you get 10 steps per epoch and 200 total: 10× fewer updates, 10× less noise per step.

2. Reading the curve

CurveDiagnosisAction
Falls, then risesOverfittingEarly stop, regularise
Spikes to NaNη too high÷10, add warmup
Dead flat at −ln(1/C)Uniform outputCheck lr, labels, zero_grad
Falls then plateaus highUnderfitCapacity ↑, schedule η ↓

A flat loss of 0.693 on a binary task is −ln 0.5: the model outputs 0.5 for everything. It is not "slow", it is not moving at all.

3. The learning-rate ladder

When nothing works, try η ∈ {1e-2, 1e-3, 1e-4} before changing architecture. A factor-of-10 sweep finds the order of magnitude in three runs; refinement after that is noise-chasing.

The trap

Most common wrong mental model

"The optimizer remembers nothing, so zeroing is cosmetic." PyTorch accumulates gradients by default. Skip zero_grad() and each step uses the sum of all previous batches' gradients — a different, usually worse, algorithm.

Second trap: measuring accuracy in train() mode. Dropout and batch norm behave differently at inference; forgetting model.eval() makes your validation number wrong, not just noisy.

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. 50,000 examples, batch size 250, 8 epochs. How many parameter updates?
    Answer

    50000/250 = 200 steps per epoch, × 8 = 1,600 updates. Epochs alone tell you nothing without the batch size.

  2. Loss is 0.693 and perfectly flat on binary cross-entropy. What is the model outputting, and name two causes.
    Answer

    Probability 0.5 for every input. Causes: learning rate far too high (weights oscillate), or a broken gradient path (missing activation, detached tensor, forgotten zero_grad).

  3. What does opt.zero_grad() prevent?
    Answer

    Accumulation. Without it, step t uses the sum of gradients from steps 1…t, so the effective learning rate grows over time and training destabilises.
