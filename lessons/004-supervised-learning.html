Supervised learning as function fitting

Why this matters— the objective

Every model in this course — a spam filter, a translation system, a Q-network — is the same four-part object. Name the four parts and you can read a paper's method section instead of guessing at it. Supervised learning is the pattern behind them all: a bank scores loan applications, a hospital flags scans, a phone predicts the next word. In each case somebody collected examples where the right answer was known, and the work is to find a rule that reproduces those answers and keeps holding on new ones. The vocabulary changes by field — "regression", "classification", "fine-tuning" — while the structure underneath stays put.

The failure it prevents. An exam question hands you "predict next month's sales from 14 store features, using three years of records" and asks for the four objects with shapes. An answer saying "the model learns the pattern" scores nothing, because no object is named. In code the same gap shows up as a model that trains happily and predicts the wrong column: the loss was computed against a misaligned y, or a target leaked into X. Writing four lines before any code catches both.

The one core idea— the objective

A supervised model is a guess-machine with adjustable dials. You show it an input, it produces an output, and a loss function scores how far that output sits from the recorded answer. Training turns the dials — the parameters θ, the numbers the model actually stores — in whichever direction lowers the average score. There is no lookup table and no understanding, only a fixed shape of function whose dials are tuned until its mistakes are small.

In one line: pick θ so that f_θ turns X into something close to y, judged by L. With 10,000 emails, 2 features and 3 dials, training squeezes those rows into 3 numbers, so the model's whole memory is w = [2, −0.01] and b = −1.

f_θ(X) ≈ y, with θ chosen to lower L

Four objects — data, model, loss — and the parameters training tunes.

How it actually works— the objective

Six steps: the four objects on the line (X, y, f_θ, L), then the two moves that connect them.

Step 1 — Collect the inputs as a matrix X

X holds one row per example and one column per feature, so 10,000 emails with 2 features give a 10,000 × 2 matrix. Features must be numbers, so text and categories are encoded first, and that encoding decides what the model can notice. Rows shuffle freely; columns keep one fixed order — a transposed 2 × 10,000 X trains without error while pairing emails with the wrong feature. Inputs alone still say nothing about the answer.

Step 2 — Record the targets as a vector y

y holds one value per row of X: 10,000 labels, 1 for spam and 0 for ham. Its type fixes the task — continuous values mean regression, a small label set means classification — and the loss must match that type. Shift y by one row and every email trains against its neighbour's label, so the loss plateaus near a coin flip. With both objects fixed, nothing yet maps one to the other.

Step 3 — Choose a hypothesis class for f_θ

The hypothesis class is the set of functions you allow the model to be: a linear model draws straight boundaries, a 3-layer network curved ones, a tree staircase ones. Choosing it is a promise about what is representable, made before data arrives — no amount of training lets a straight line separate two interleaved spirals. A class alone carries no numbers, so there is nothing yet to score.

Step 4 — Define the loss L that prices mistakes

L takes one prediction and one target and returns 0 when they agree, more as they diverge: squared error suits continuous targets, cross-entropy suits probabilities. Averaging L over all n rows gives the empirical risk, the single number training minimises — three cross-entropies of 0.105, 0.223 and 0.511 average to 0.839/3 = 0.280. On a yes/no task, squared error rewards confident wrong answers while the gradient fades.

θ* = argmin_θ (1/n) Σᵢ L(f_θ(xᵢ), yᵢ)(sigma)

Step 5 — Search over θ by gradient descent

Start with random dials, measure how the average loss responds to each parameter, and step downhill: θ ← θ − η∇L(eta), where η is the learning rate and ∇L(nabla) the gradient of the loss with respect to θ. Three dials could be found by grid search; 300 million cannot, so the gradient is the only affordable direction finder — and η = 10 instead of 0.1 sends the loss upward.

Worked example— the objective

1. One email, end to end

One email arrives and the model must answer one question: spam or not? Three moves — score the evidence, squash the score into a probability, price the answer against the label. A one-dial version first, so the arithmetic fits in your head: the email contains "free" (1) or it does not (0), with w = 2, b = −1.

StepValue
z = 2(1) + (−1) = 2 − 11.0
p = 1/(1 + e−1) = 1/1.3680.731
Loss if spam: −ln(0.731)0.313
Loss if ham: −ln(0.269)1.313

Read it as a sentence. "Free" is worth 2 points of evidence and the bias takes 1 away, so the score is 2 − 1 = 1.0 — mildly suspicious. The squash turns 1.0 into 0.731, "73% spam", which costs 0.313 if the email really is spam and 1.313 if it is ham: 73% spam is a confidently wrong answer for a ham email.

Now the real email. Features x = [1, 50] — "contains 'free'" and "length in words" — with w = [2, −0.01], b = −1.

StepValue
z = 2(1) + (−0.01)(50) + (−1) = 2 − 0.5 − 10.5
p = 1/(1 + e−0.5) = 1/1.6070.622
Loss if spam: −ln(0.622)0.475
Loss if ham: −ln(0.378)0.973

Row 1 — add the evidence. 2(1) = +2 for "free"; (−0.01)(50) = −0.5 for length, 50 words at −0.01 each; −1 for the bias. Add the three: 2 − 0.5 − 1 = 0.5.

Row 2 — squash it. e−0.5 = 0.607, so 1/(1 + 0.607) = 0.622: 62% spam. A score of 0 lands on 0.5, positives above it, negatives below.

Rows 3 and 4 — price it. The label picks the row: −ln(0.622) = 0.475 if the email is spam, −ln(0.378) = 0.973 if it is ham. Same prediction, a bigger bill, because 62% spam is a poor answer for a ham email.

Why the log. −ln p is 0 when you are confident and right, and grows without limit when you are confident and wrong: p = 0.9 costs 0.105, p = 0.5 costs 0.693, p = 0.1 costs 2.303. That slope is what training follows.

What to notice. The length feature, weighted at −0.01, subtracted 0.5 from the score, so this model reads long emails as slightly less spammy — and being wrong about ham costs 0.973 against 0.475 for spam, which is why training drifts borderline emails toward "ham".

3. Check yourself

On paper first: reading the tables is not producing them.

  1. Same one-dial email, but w = 1, b = 0. What are the score, the probability and the loss if it is spam?
    Answer

    z = 1(1) + 0 = 1, so p = 0.731 and the loss is 0.313 — identical to the first table. Only the score decides the prediction, not how the two numbers split to produce it.

  2. Example 2 has p = [0.9, 0.2, 0.6]. If the middle prediction moves from 0.2 to 0.8, what happens to the average loss?
    Answer

    It jumps from 0.280 to (0.105 + 1.609 + 0.511)/3 = 0.742: with y = 0 the term is −ln(1 − p), so a confidently wrong answer costs 1.609.

  3. On this same three-email set, what does a model that always outputs 0.5 score — and is that better or worse than 0.280?
    Answer

    −ln 0.5 = 0.693 per row, so 0.693. Worse than 0.280, and that is the honest baseline any classifier must beat.

The trap— the objective

Most common wrong mental model

"The model learned the data." It learned parameters. A model with more parameters than data points can score perfectly and still be useless: it memorised X without learning the mapping from X to y.

It feels right because a falling training loss is visible evidence of progress, and a model that reproduces every label looks like it has understood the pattern. But the only thing stored is θ — 3 numbers here, 10 million in a large network — chosen against rows that will never be seen again.

Correction: separate the two claims. "Training loss is low" is a statement about the search; "the mapping generalises" is a statement about new rows, and only a held-out set supports it. Underneath sits a hidden assumption — future data comes from the same distribution as training data, called i.i.d. — and breaking it makes a perfect training score worth nothing.

The tell: training accuracy 100% with test accuracy 71% is the signature, and the 29-point gap is the measurement, not rounding. A second tell is a test score that moves each time you retrain on a new seed while training loss barely moves — variance from a model with too much freedom for the number of rows.

Retrieval check— the objective

  1. For "predict house price from 8 features", name all four objects with shapes.
    Answer

    X: n×8 · y: n×1 continuous · f_θ: a linear model or gradient-boosted trees · L: squared error. If L were classification loss, you would be answering a different question.

  2. Your model gets 100% training accuracy and 71% test accuracy. Is it a good model?
    Answer

    No. The 29-point gap says it memorised rather than generalised. The 71% number is the only one that describes the deployed system.

  3. What does changing the hypothesis class change — the data, the loss, or what the model is capable of representing?
    Answer

    Only the last one. Data and loss can stay identical while moving from linear to tree to neural, and the achievable functions change completely.
