Supervised learning as function fitting

You can write down (X, y, f_θ, L) for any supervised task and say what is being learned.

Why this matters

Every model in this course — a spam filter, a translation system, a Q-network — is the same four-part object. Name the four parts and you can read a paper's method section instead of guessing at it. Supervised learning is the pattern behind them all: a bank scores loan applications, a hospital flags scans, a phone predicts the next word. In each case somebody collected examples where the right answer was known, and the work is to find a rule that reproduces those answers and keeps holding on new ones. The vocabulary changes by field — "regression", "classification", "fine-tuning" — while the structure underneath stays put.

The failure it prevents. An exam question hands you "predict next month's sales from 14 store features, using three years of records" and asks for the four objects with shapes. An answer saying "the model learns the pattern" scores nothing, because no object is named. In code the same gap shows up as a model that trains happily and predicts the wrong column: the loss was computed against a misaligned y, or a target leaked into X. Writing four lines before any code catches both.

The one core idea

A supervised model is a guess-machine with adjustable dials. You show it an input, it produces an output, and a loss function scores how far that output sits from the recorded answer. Training turns the dials — the parameters θ, the numbers the model actually stores — in whichever direction lowers the average score. There is no lookup table and no understanding, only a fixed shape of function whose dials are tuned until its mistakes are small.

In one line: pick θ so that f_θ turns X into something close to y, judged by L. With 10,000 emails, 2 features and 3 dials, training squeezes those rows into 3 numbers, so the model's whole memory is w = [2, −0.01] and b = −1.

How it actually works

Take it in six parts: the four objects on the line (X, y, f_θ, L), then the two steps that connect them.

Part 1 — Collect inputs as a matrix X

X holds one row per example and one column per feature, so 10,000 emails with 2 features give a 10,000 × 2 matrix. Features must be numbers, so text and categories are encoded first, and that encoding decides what the model can notice. Rows can be shuffled freely; columns must keep one fixed order.

Why this part exists: every later shape is checked against these two numbers, and a transposed X of 2 × 10,000 would train without error while pairing emails with the wrong feature.

Part 2 — Record targets as a vector y

y is one value per row of X, so 10,000 labels: 1 for spam, 0 for ham. The type of y fixes the task — continuous values mean regression, a small label set means classification — and the loss must match that type.

Why this part exists: shift y by one row and every email is trained against its neighbour's label, so the loss plateaus near a coin flip and extra training cannot rescue it.

Part 3 — Choose a hypothesis class for f_θ

The hypothesis class is the set of functions you allow the model to be. A linear model draws straight boundaries, a 3-layer network draws curved ones, a tree draws staircase ones. Choosing the class is a promise about what is representable, made before data arrives.

Why this part exists: no amount of training lets a straight line separate two interleaved spirals, so a mismatch here surfaces much later as a loss that refuses to fall.

Part 4 — Define the loss L that scores mistakes

L takes one prediction and one target and returns 0 when they agree, more as they diverge. Squared error suits continuous targets; cross-entropy suits probabilities. Averaging L over all n rows gives the empirical risk, the single number training minimises:

θ* = argmin_θ (1/n) Σᵢ L(f_θ(xᵢ), yᵢ)

Why this part exists: the loss is the only definition of "better", so a mismatch optimises the wrong thing — squared error on a yes/no task rewards confident wrong answers while the gradient fades.

Part 5 — Search over θ by gradient descent

Start with random dials, measure how the average loss responds to each parameter, and step downhill: θ ← θ − η∇L, where η is the learning rate. Repeat for a set number of epochs, one pass over the 10,000 rows each.

Why this part exists: 3 dials could be found by grid search, but 300 million cannot; the gradient is the only affordable direction finder, and a learning rate of 10 instead of 0.1 sends the loss upward.

Part 6 — Report on data the search never touched

Split before training: roughly 60% train, 20% validation for choosing settings, 20% test for one final number. Training loss says whether the search worked; test loss says whether it mattered.

Why this part exists: parameters were chosen to fit the training rows, so their error there is biased low — with 3 dials that gap is a fraction of a point, but with 10 million dials it can be 30 points wide.

The length feature, weighted at −0.01, subtracted 0.5 from the score, so this model reads long emails as slightly less spammy. Being wrong about a ham email costs 0.973 while being wrong about spam costs 0.475, which is why training drifts borderline emails toward "ham".

The trap

Most common wrong mental model

"The model learned the data." It learned parameters. A model with more parameters than data points can score perfectly and still be useless: it memorised X without learning the mapping from X to y.

It feels right because a falling training loss is visible evidence of progress, and a model that reproduces every label looks like it has understood the pattern. But the only thing stored is θ — 3 numbers here, 10 million in a large network — chosen against rows that will never be seen again.

Correction: separate the two claims. "Training loss is low" is a statement about the search; "the mapping generalises" is a statement about new rows, and only a held-out set supports it. Underneath sits a hidden assumption — future data comes from the same distribution as training data, called i.i.d. — and breaking it makes a perfect training score worth nothing.

The tell: training accuracy 100% with test accuracy 71% is the signature, and the 29-point gap is the measurement, not rounding. A second tell is a test score that moves each time you retrain on a new seed while training loss barely moves — variance from a model with too much freedom for the number of rows.

Retrieval check

  1. For "predict house price from 8 features", name all four objects with shapes.
    Answer

    X: n×8 · y: n×1 continuous · f_θ: a linear model or gradient-boosted trees · L: squared error. If L were classification loss, you would be answering a different question.

  2. Your model gets 100% training accuracy and 71% test accuracy. Is it a good model?
    Answer

    No. The 29-point gap says it memorised rather than generalised. The 71% number is the only one that describes the deployed system.

  3. What does changing the hypothesis class change — the data, the loss, or what the model is capable of representing?
    Answer

    Only the last one. Data and loss can stay identical while moving from linear to tree to neural, and the achievable functions change completely.
