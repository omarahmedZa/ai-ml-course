Architecture families: what each one assumes

You can state what MLP, CNN and RNN each assume about data, and choose one for a task.

Why this matters

Choosing an architecture is the first decision of any project, and it is a decision about your data rather than about fashion. Each family bakes in an assumption: that nearby pixels belong together, that the same pattern can appear anywhere, that step 5 depends on step 4.

Get the assumption wrong and the model fights the problem instead of solving it. Convolve 40 survey columns and the filter slides across "neighbouring" columns that were never neighbours, so it learns nothing stable; shuffle the column order and accuracy can move by 20 points. The exam version asks you to justify the choice rather than name it: "30 numeric columns, no ordering — which family first, and why not a CNN?"

The one core idea

Picture two kinds of form. One has a separate question for every position in the input, so moving the input moves every question. The other has a single question asked at every position — "is there an edge here?" — and the answer means the same wherever it lands. An architecture is that choice, made once.

In one line: an architecture is a promise about which changes leave the answer alone, and that promise is what saves you parameters. A 3×3 filter from 64 channels to 64 outputs needs 36,864 weights and works at any image size; the dense layer on the same 224×224×64 input needs 205,520,896.

How it actually works

Four families, one question each: what structure does your data actually have?

Part 1 — An architecture is a prior

A prior is a statement you make before seeing any data. "Shifting this image by two pixels does not change what it is" is a prior; so is "these 40 columns are unrelated". Every weight you avoid is a weight you no longer have to learn from examples, so a true prior is worth more than extra rows.

Why this part exists: without naming the assumption you cannot tell whether a family fits the problem, and the choice collapses into picking whatever is fashionable.

Part 2 — The MLP assumes nothing

A multilayer perceptron is y = W₂φ(W₁x), and every input connects to every output. A layer from 40 inputs to 64 has 40 × 64 = 2,560 weights, each learned independently. Permuting the input features changes the function completely: the network has no idea that column 3 sits beside column 4.

Why this part exists: it is the honest baseline. When features genuinely have no order, assuming nothing is the correct prior, and a tree ensemble or an MLP is hard to beat.

Part 3 — The CNN shares one filter everywhere

A convolutional filter of shape k × k × C_in is applied at every spatial position. A 3×3 filter from 64 channels to 64 outputs has 3 × 3 × 64 × 64 = 36,864 weights, and that one filter is reused at all 50,176 positions of a 224×224 map. Locality comes from the filter's small size; translation comes from reusing it.

Why this part exists: without sharing you would need a separate edge detector for every pixel, which is both enormous and untrainable.

Part 4 — Stride and pooling shrink the map

A 3×3 convolution with stride 1 and no padding turns a 224×224 map into 222×222. Stride 2 with padding 1 halves it to 112×112, and every later filter then covers twice as much of the original image.

Why this part exists: without downsampling each layer costs as much as the first, and the region any single unit can see never grows enough to contain a whole object.

Part 5 — The RNN reuses one cell per step

A recurrent network computes h_t = φ(W_h h_{t−1} + W_x x_t) with the same two matrices at every timestep. A hidden size of 128 with 64 inputs costs 24,704 parameters whether the sequence runs for 10 steps or 10,000. The price is that step 20 cannot start until step 19 has finished.

Why this part exists: sharing across time is what lets the model handle sequence lengths it never saw in training; the sequential dependency is what that sharing costs.

Part 6 — Attention treats the sequence as a set

Attention lets every position read every other position directly, so all of them compute in parallel. Position information must then be added explicitly, because a set has no order. The cost is quadratic in length: doubling from 1,000 to 2,000 tokens takes the attention matrix from one million entries to four million.

Why this part exists: an RNN's fixed-size state squeezes everything it has seen into one vector, so detail from 200 steps back is mostly gone; attention keeps every position addressable.

Part 7 — Choose by structure, then measure

Ask what stays true when the input changes. Shift an image and it is the same object, so convolve. Shuffle the columns of a table and each row still means the same thing, so do not. Then count parameters and run the cheapest baseline before committing.

Why this part exists: a mismatched prior does not fail loudly; it quietly loses to a simpler model you could have trained in an afternoon.

1. The parameter argument for convolution

Both rows below produce 64 output channels from the same 224×224×64 input.

LayerArithmeticWeights
3×3 conv, 64 → 643 × 3 × 64 × 6436,864
Dense, 3,211,264 → 643,211,264 × 64205,520,896
Ratio205,520,896 ÷ 36,864≈ 5,575×

What to notice. The dense layer is about 5,500 times larger, and it still has to relearn an edge detector separately at each of the 3,211,264 positions. Double the image side to 448 and the convolution stays at 36,864 weights while the dense layer becomes 12,845,056 × 64 = 822,083,584 — a ratio of about 22,300×. That is the concrete meaning of a prior: the conv layer already knows the answer does not depend on where it looks.

2. What stride and padding do to the shape

One formula covers all three rows: out = (W − k + 2p) / s + 1, rounded down.

What to notice. Padding 1 exactly cancels the shrink from a 3×3 filter, which is why it is the default: the map keeps its size and only the channel count changes. Stride 2 does the opposite job deliberately — (224 − 3 + 2)/2 + 1 = 112, a quarter of the values, since 112 × 112 × 64 = 802,816 against 3,211,264.

3. Why recurrence is cheap

What to notice. Unrolled over 200 timesteps, a network with separate weights per step would need 200 × 24,704 = 4,940,800 parameters and could never generalise to step 201. Sharing keeps the count at 24,704 for any length. What you pay instead is time: 200 steps means 200 sequential passes, which is exactly the cost attention removes.

The trap

Most common wrong mental model

"Deeper and newer is better." It feels right because every result you read about uses the newest block. But an architecture is only as good as the match between its prior and your data's structure.

Correction: a transformer on 800 tabular rows loses to logistic regression, and a CNN on shuffled columns is strictly worse than an MLP of the same width. Start with the simplest family whose assumptions are true, then spend the complexity budget only where the baseline is clearly short.

Second trap: assuming an RNN "remembers" because it is recurrent. Its state is a fixed-size vector, so information from 200 steps ago is mostly overwritten — attention was invented to fix that.

The tell: shuffle your input columns and retrain. If accuracy moves by double digits, the architecture is assuming an adjacency the data does not have, and that one test tells you more than any benchmark table. The second tell is a first convolutional layer whose learned filters look like television static after training — filters that never specialised are filters that had nothing local to find.

Retrieval check

  1. Why does a CNN use far fewer parameters than a dense layer on the same image?
    Answer

    Weight sharing: one small filter is reused at every spatial position instead of a separate weight per pixel per output. It also encodes translation invariance for free.

  2. Your data is 30 numeric columns from a survey. Which family first, and why not a CNN?
    Answer

    Trees/GBM first. There is no spatial adjacency, so convolution's core assumption is false — the "neighbouring" columns are arbitrary.

  3. What does an RNN assume that a transformer does not?
    Answer

    That order is processed sequentially and the same transition applies at each step. A transformer treats the sequence as a set plus positional information, which allows parallel computation.
