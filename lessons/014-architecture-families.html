Architecture families: what each one assumes

You can state what MLP, CNN and RNN each assume about data, and choose one for a task.

Why this matters

Choosing an architecture is choosing which invariances you get for free. Get it right and the model needs less data; get it wrong and it fights the problem — a CNN on tabular data, an MLP on images.

The one core idea

An architecture is a prior: a statement about which transformations should not change the answer. CNNs assume locality and translation; RNNs assume order and shared dynamics; MLPs assume nothing.

How it actually works

MLPCNNRNN
AssumesFeatures independent, no spatial/order structureLocal patterns, same pattern anywhereSequence order matters; same rule each step
Weight sharingNoYes — one filter slides everywhereYes — one cell reused per timestep
Parallel over inputYesYesNo — strictly sequential
Best forTabular, small fixed vectorsImages, audio spectrograms, 1-D signalsTime series, text (historically)
  • MLP: y = W₂φ(W₁x). Permuting input features changes the function completely — it has no idea that feature 3 sits next to feature 4.
  • CNN: a filter of shape k×k×C_in is applied at every position. A 3×3 filter over 64 channels to 64 outputs has 3·3·64·64 = 36,864 weights and works on any image size.
  • RNN: h_t = φ(W_h h_{t−1} + W_x x_t). The same weights at every step, so the model generalises across sequence lengths.
  • Transformers (Unit 7) drop the sequence assumption and use attention — parallel, but with O(n²) cost.

Worked example

1. The parameter argument for convolutions

One 3×3 conv layer, 64 in, 64 out: 36,864 weights. The dense layer on the same 224×224×64 input (3,211,264 values) to 64 outputs needs 3,211,264 × 64 ≈ 205 million — 5,500× more, and it would have to relearn an edge detector at every pixel.

2. Choosing under constraint

TaskPickReason
Churn prediction, 40 columnsGBM (or MLP)No spatial structure; trees handle mixed scales
X-ray classification, 5k imagesCNN (pretrained)Locality + transfer beats training from zero
Sensor stream, 10 Hz1-D CNN or GRULocal temporal patterns; short memory
Machine translationTransformerLong-range dependencies, parallel training

The trap

Most common wrong mental model

"Deeper/newer is better." Architecture must match the data's structure. A transformer on 800 tabular rows will lose to logistic regression, and a CNN on shuffled columns is strictly worse than an MLP.

Second trap: assuming an RNN "remembers" because it is recurrent. Its state is a fixed-size vector; information from 200 steps ago is mostly gone (topic 17).

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. Why does a CNN use far fewer parameters than a dense layer on the same image?
    Answer

    Weight sharing: one small filter is reused at every spatial position instead of a separate weight per pixel per output. It also encodes translation invariance for free.

  2. Your data is 30 numeric columns from a survey. Which family first, and why not a CNN?
    Answer

    Trees/GBM first. There is no spatial adjacency, so convolution's core assumption is false — the "neighbouring" columns are arbitrary.

  3. What does an RNN assume that a transformer does not?
    Answer

    That order is processed sequentially and the same transition applies at each step. A transformer treats the sequence as a set plus positional information, which allows parallel computation.
