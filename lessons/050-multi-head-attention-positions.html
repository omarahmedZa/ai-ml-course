Multi-head attention & positions

You can compute one attention head, say what multiple heads buy, and explain how position enters the model.

Language & TransformersAttention & Blocks

Why this matters— attention

A single attention head expresses one pattern of "which token should I look at?", averaged into one output. Language needs several at once: the verb wants its subject, the adjective its noun, the pronoun its antecedent. Multi-head attention runs those searches in parallel and concatenates the results. Separately, attention is order-blind: shuffle the tokens and, without positional information, every output is merely shuffled too.

The failure it prevents. An exam asks why multi-head attention is not just a more expensive single head. "More heads means more capacity" is wrong: the total width is fixed, so heads partition the same budget. The marks come from the split-and-concatenate arithmetic. In code the same gap is a model that scores well on bag-of-words tasks and fails on anything order-dependent, because the positional encoding was dropped.

The one core idea— attention

Attention is a soft lookup. Write Q for queries (what each position looks for), K for keys (what each position offers), and V for values (what each position passes on). All three are linear projections of the same token vectors. Scores are QKᵀ/√d_k(square root), softmax turns each row into weights, and the output is softmax(QKᵀ/√d_k)V — each position's value, mixed in the proportions the weights specify.

In one line: one head is one weighted average; several heads average in different learned subspaces; position is added because the average cannot tell order. With d_model = 512 and h = 8, each head works in 64 dimensions, and the eight outputs are concatenated back to 512 before a final projection.

head = softmax(QKᵀ/√d_k)V · multi-head = concat then W_O

Heads split the width, not multiply it. Position enters by adding a vector or rotating Q and K.

How it actually works— attention

Six parts: projections, scores, one head, the join, why it helps, position.

Part 1 — Three projections of the same input

Each token vector x of width d_model is multiplied by three learned matrices W_Q, W_K, W_V, producing a query, a key and a value. The three have different jobs, so they get different weights; stacking the results for all n tokens gives Q, K, V of shape n × d_k. Why this part exists: a token can ask one question, advertise a different property, and pass on a third — collapsing them into one vector removes that freedom.

Part 2 — Scores, scaling and the mask

QKᵀ gives an n × n matrix: entry (i, j) is the dot product of query i with key j. Divide by √d_k, because a dot product of d_k random terms grows with √d_k and large scores saturate the softmax. Softmax each row so weights sum to 1. A causal mask sets entries above the diagonal to −∞ before the softmax, zeroing them. Why this part exists: without scaling, gradients vanish at width; without the mask, a decoder reads the answer.

Part 3 — One head is a weighted average of values

Row i of the weight matrix says how much position i attends to each position. Multiply those weights by the value vectors and sum: the output is a mixture of all values, dominated by the ones attended to. Why this part exists: this is the entire operation; everything else is how to run several and where to put the result.

Part 4 — Split, run, concatenate, project

With h heads, project into d_head = d_model/h dimensions per head, run attention independently, concatenate the h outputs to width d_model, then multiply by W_O. At d_model = 512, h = 8: four projections per head cost 4 × 512 × 64 = 131,072, so eight heads cost 1,048,576 — exactly what one 512-wide head costs. Why this part exists: this arithmetic answers "is multi-head just bigger?" — no, it is the same size, differently factored.

Part 5 — What several heads actually buy

Each head has its own initialization and gradient, so they specialize: one tracks the previous token, one links verbs to subjects, one attends to punctuation. The subspaces need not differ — many heads are redundant and can be pruned — but the ensemble is more expressive than one average. Why this part exists: heads are parallel feature detectors, not a committee of interpretable specialists.

Part 6 — Position has to be injected

Attention treats its input as a set: permute the tokens and every output is permuted the same way. To break that, add a position vector to each embedding, or rotate queries and keys by an angle proportional to position. Rotary position embedding (RoPE) rotates the query at position m and the key at position n, so their dot product depends on m − n. Why this part exists: without it, "dog bites man" and "man bites dog" are the same bag of tokens.

Worked example— attention

1. One head on two tokens

Take d_k = 2, so the scale is √2 = 1.414. Query for token 1 is q₁ = [1, 0]; keys are k₁ = [1, 0] and k₂ = [0, 1]; values are v₁ = [2, 0] and v₂ = [0, 1].

StepArithmeticValue
Raw scoresq₁·k₁ = 1, q₁·k₂ = 0[1, 0]
Scaled[1, 0] / 1.414[0.707, 0]
Exponentiated[e^0.707, e^0][2.028, 1.0]
Weights[2.028, 1.0] / 3.028[0.670, 0.330]
Output0.670[2, 0] + 0.330[0, 1][1.340, 0.330]

Read it as a sentence. Query 1 matches key 1 exactly and key 2 not at all, so the raw scores are 1 and 0. Scaling and exponentiating give a ratio near 2 to 1, and the weights are 67% and 33%. The output is two-thirds of value 1 and one-third of value 2: [1.34, 0.33]. Softmax never gives zero, which is why masking uses −∞ rather than 0.

2. A second head, and the join

Suppose head 2 uses q₂ = [0, 1] with the same keys and values. Its scores are [0, 0.707], so its weights are [0.330, 0.670] and its output is 0.330[2, 0] + 0.670[0, 1] = [0.660, 0.670]. Concatenate: [1.340, 0.330, 0.660, 0.670].

Apply W_O with rows [1, 0, 1, 0] and [0, 1, 0, 1]. The first coordinate is 1.340 + 0.660 = 2.000; the second is 0.330 + 0.670 = 1.000. The two heads, which looked at opposite tokens, recombine into [2, 1] — the sum of the values. Heads see different mixtures, and W_O decides how to combine them.

Position check. Swap the tokens with no position information and the outputs are the same, reordered. The model cannot tell "A then B" from "B then A". Adding p₁ = [0, 0] and p₂ = [1, 0] changes the queries, so order matters.

The trap— attention

Most common wrong mental model

"More heads means more capacity, so a 32-head model computes four times as much as an 8-head model." At fixed d_model, heads split the same width and the projection parameter count is unchanged. A 32-head layer does the same multiply-adds as an 8-head layer; it differs in factoring, not in amount. Many heads are redundant, and pruning a third often costs almost nothing.

It feels right because "multi" suggests multiplication, and more heads do help up to a point. The help comes from several independent subspaces early in training, not extra arithmetic.

Correction: price a head by d_head = d_model/h. For more capacity, raise d_model or the layer count; for more variety, raise h and accept narrower heads. Never read a single attention map as an explanation — it is one layer's routing, not a causal account.

The tell: attention maps from different heads that are nearly identical — the heads collapsed. A second is output unchanged when you shuffle the input tokens; position is missing or added too late. A third is an "interpretability" claim built on one head while ablating it leaves the loss flat.

Retrieval check— attention

  1. With d_model = 768 and h = 12, what is d_head, and why divide scores by √d_head?
    Answer

    d_head = 64. Dot products of 64 terms have standard deviation around √64 = 8, and dividing by 8 keeps scores near unit scale so the softmax does not saturate.

  2. Why does removing positional information make a transformer unable to distinguish word order?
    Answer

    Attention is permutation-equivariant: permuting the inputs permutes the outputs identically. Without position vectors or rotations, the model sees a set, not a sequence.

  3. What does RoPE make the query-key dot product depend on?
    Answer

    The relative offset m − n. Rotating each vector by an angle proportional to its position makes the inner product a function of the difference, not the absolute positions.

Build it in Colab— attention

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. Sections, plots and line-by-line notes — run the cells in order, then change the number of heads and rerun.

import numpy as np
q = np.array([1.0, 0.0])                   # query for token 1
K = np.array([[1.0, 0.0], [0.0, 1.0]])     # two keys
V = np.array([[2.0, 0.0], [0.0, 1.0]])     # two values
s = K @ q / np.sqrt(2)                     # scaled scores
w = np.exp(s) / np.exp(s).sum()            # softmax over keys
print(w, w @ V)                            # [0.67 0.33] [1.34 0.33]
