Probability, expectation, likelihood

You can explain why a loss is a negative log-likelihood, and read mean and variance off a distribution.

Why this matters

A classifier does not output a label; it outputs a distribution over labels. A loss does not measure "wrongness"; it measures surprise. Without that framing, softmax and cross-entropy are arbitrary formulas to memorise.

The one core idea

A model assigns probability to what actually happened. The loss is how surprised the model was — and surprise is −log p.

How it actually works

  • Random variable = an outcome with a number attached. A PMF gives each discrete outcome a probability; it sums to 1. A PDF is the continuous version; it integrates to 1.
  • Expectation E[X] = Σ x·p(x) = the long-run average. Variance = E[(X − E[X])²] = spread.
  • Likelihood L(θ) = p(data | θ) — the probability of the observed data, viewed as a function of the parameters. Data fixed, parameters varying.
  • Independence multiplies probabilities. Products of many small numbers underflow, so take logs: they turn into sums.
  • Maximum likelihood = pick θ maximising L = minimising −log L (NLL).
  • Cross-entropy is exactly NLL for a softmax output. Nothing new is happening.
NLL(θ) = −Σᵢ log p_θ(yᵢ | xᵢ)

Worked example

1. A biased coin

Model says p(heads) = 0.7. You observe 3 heads in 3 tosses.

ModelLikelihoodNLL = −ln L
p = 0.70.3431.07
p = 0.50.1252.08

Lower NLL wins, so the data prefer p = 0.7. With 3 observations the evidence is weak — 3 heads also happens 12.5% of the time under a fair coin.

2. A classifier

Logits z = [2, 1, 0] → softmax:

ClasseᶻpLoss if true
17.3890.6650.41
22.7180.2451.41
31.0000.0902.41

If the true class is 1, loss is −ln 0.665 = 0.41. If it is 3, loss is 2.41 — the model was confident and wrong, so it pays more. Confidence is only rewarded when it is correct.

The trap

Most common wrong mental model

"Likelihood is the probability that my model is correct." It is not. Likelihood is P(data | parameters). The probability of the model given the data is a different quantity (Bayes), and nobody computes it in training.

Second trap: thinking squared error and cross-entropy are unrelated. Minimising squared error is maximum likelihood under a Gaussian noise assumption. Same principle, different distribution.

Retrieval check

  1. A model says p(heads) = 0.5. Two tosses land heads. What is the NLL?
    Answer

    L = 0.25, so NLL = −ln 0.25 = 1.386. Two independent observations multiply; the log turns that into two additions of 0.693.

  2. Why do we take the log of a likelihood before optimising it?
    Answer

    Products of many probabilities underflow to zero in floating point, and derivatives of products are messy. Logs turn products into sums and preserve the location of the maximum.

  3. Model A scores NLL 0.5 on the test set; model B scores 1.2. Which do you ship, and what does 1.2 mean in plain language?
    Answer

    Ship A. On average its predicted probability for the true class is e^−0.5 ≈ 0.61; B's is e^−1.2 ≈ 0.30. B is roughly twice as surprised by reality.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
for p in (0.5, 0.7):
    L = p ** 3
    print(f"p={p}: likelihood={L:.3f}  NLL={-np.log(L):.3f}")
z = np.array([2., 1., 0.])
probs = np.exp(z) / np.exp(z).sum()
print("softmax:", probs.round(3))
