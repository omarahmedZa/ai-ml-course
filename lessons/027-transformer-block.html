The Transformer block

You can name every sub-layer, its purpose, and why residual + LayerNorm are required.

Why this matters

A Transformer block is the repeating unit inside every large language model. A config file names 96 layers, a width of 12,288 and 96 heads; this lesson is the map from those three numbers to the four sub-layers that do the work.

Once you can name the parts, an architecture diagram stops being decoration. Reading "pre-LN, 96 layers, 96 heads, d_model 12,288" tells you each head is 128 numbers wide, the feed-forward layer is 49,152 wide inside, and the residual stream carries 12,288 numbers per token from the first block to the last. In an exam, "why does a block need a residual connection?" is a two-mark question with a mechanical answer about gradient paths. In a project, the missing part is usually the causal mask: training loss drops to 0.02 within an hour, the samples are fluent nonsense, and the logs show nothing unusual. The other common failure is a shape that broadcasts — adding a 512-number vector to a whole sequence without noticing — which produces plausible numbers and a model that never converges.

The one core idea

A block is a meeting followed by a memo. Attention is the meeting: every token talks to the others and leaves with a blend of what it heard. The feed-forward network is the memo: each token, alone, rewrites its own notes. The residual connection keeps the original notes on the desk so nothing is lost, and LayerNorm keeps the volume steady so no sub-layer shouts.

In one line: mix across tokens, then process each token, add both results back, normalise on the way in. At width 512 with 8 heads, each head is 64 numbers; one block holds about 3.15M parameters, and 12 of them hold about 37.8M.

How it actually works

Seven parts, in the order the numbers flow.

x → x + MHA(LN(x)) → x + FFN(LN(x)) (pre-LN form)

Part 1 — Keep a residual stream

The input x is a table of shape n × d: one row per token, 512 numbers per row, with a positional encoding added once at the bottom to record where each row sits. No sub-layer ever replaces that table; each one computes a change and adds it back, so the stream is the same shape at the top of the stack as at the bottom. Why this part exists: a chain of 96 matrix multiplies with a gain of 0.9 per layer shrinks the signal to 0.00004 of its starting size, and a gain of 1.1 blows it up 9,000-fold; the addition gives every layer a copy of the original to work from.

Part 2 — Normalise each token before its sub-layer

LayerNorm takes one token's 512 numbers, subtracts their mean, divides by their standard deviation, then multiplies by a learned scale and adds a learned shift — 512 numbers each, so 1,024 parameters per LayerNorm. It works across features inside a single token, never across the batch. Why this part exists: without it, each sub-layer shifts the typical activation size, and after a few dozen blocks the numbers entering softmax are either tiny or enormous.

Part 3 — Mix across tokens with attention

Multi-head attention is topic 26, run 8 times in parallel: 8 heads of 64 dimensions rebuild the 512-wide stream, and an output matrix mixes the heads back together. Each token's row is rewritten as a weighted blend of every token's value. Why this part exists: without this sub-layer, positions could never exchange information, and the model would score each token as if it stood alone.

Part 4 — Mask the future

The score matrix is n × n. For a 5-token sequence that is 25 cells, and the causal mask keeps the 15 on and below the diagonal, setting the other 10 to −∞ before softmax. Why this part exists: the training target for position 3 is the token at position 4, so an unmasked model can read the answer off its own input, drive the loss to near zero, and then fail completely at generation time when no future exists.

Part 5 — Process each token with the FFN

A feed-forward network expands 512 numbers to 2,048, applies GELU (a smooth nonlinearity), and projects back to 512. Its two matrices hold 2 × 512 × 2,048 = 2,097,152 parameters, which is two-thirds of the block. Why this part exists: attention only averages vectors that already exist, so without a nonlinear per-token step the whole stack could be collapsed into one weighted average.

Part 6 — Add, and stack the block

Each of the two sub-layers ends with an addition, then the next block repeats the pattern with its own weights. Twelve blocks at width 512 give roughly 37.8M parameters; GPT-3 stacks 96 blocks. Why this part exists: one block can only combine what its heads happen to notice, and depth is what lets a later block build on a relation an earlier block discovered.

Part 7 — Choose where the norm goes

Pre-LN normalises the input to each sub-layer, inside the branch: x + MHA(LN(x)). Post-LN normalises after the addition instead. Modern models use pre-LN because the residual path stays a clean chain of additions from the loss back to the first block. Why this part exists: post-LN puts a normalisation on that path at every block, so very deep post-LN models need a long learning-rate warmup.

What to notice. Attention looks like the star of the block, yet it holds one-third of the parameters and the FFN holds two-thirds: 2,097,152 ÷ 3,147,776 = 0.666. The four attention matrices are all square, which is why they add up to exactly 4d². Scaling width from 512 to 1,024 multiplies every entry by four.

That is the point — the next matrix multiply cares about direction, not magnitude — and it is also why the residual matters, since x itself still holds [2, 4, 6, 8] for the addition that follows.

The trap

Most common wrong mental model

"Attention makes the model order-aware." It feels right because word order obviously changes meaning, and attention weights do change when you reorder a sentence.

The correction is that attention is permutation-equivariant: shuffle the input tokens and the outputs shuffle with them, unchanged in value. Order enters only through positional encodings added to the token vectors, which is why they are not an optional extra. A second trap is treating LayerNorm and BatchNorm as interchangeable. LayerNorm normalises across features within one token, so it behaves identically for a batch of 1 and a batch of 1,000 — essential when generating one token at a time.

The tell: delete the positional encodings and retrain. Accuracy on order-sensitive tasks collapses to roughly what a bag of words would score, while the code still runs and the loss still falls. If someone claims a block "understands sequence" from attention alone, ask them where the position information enters — there is exactly one answer.

Retrieval check

  1. Why does the FFN hold most of the parameters even though attention gets the attention?
    Answer

    It expands to 4d and back, twice the matrices of the attention projections at 4× the width: 2·d·4d versus 4·d².

  2. What happens to next-token prediction if the causal mask is removed?
    Answer

    The model sees the target token in its own input, so the loss goes to near zero during training. At generation time the future is absent, and quality collapses.

  3. Why is pre-LN preferred for very deep transformers?
    Answer

    The residual path stays unnormalised, so gradients flow cleanly to early layers. Post-LN requires careful warmup and still destabilises beyond a few dozen blocks.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
def softmax(z):
    e = np.exp(z - z.max(-1, keepdims=True)); return e / e.sum(-1, keepdims=True)
def layernorm(x, eps=1e-5):
    mu, var = x.mean(-1, keepdims=True), x.var(-1, keepdims=True)
    return (x - mu) / np.sqrt(var + eps)
