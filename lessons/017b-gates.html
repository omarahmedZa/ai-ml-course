f, i, o — the gates

You can compute one LSTM cell update, and say why adding is easier to train than multiplying.

Where this sits

gates: f, i, o = σ( W [ht−1, xt] + b ) ct = f ⊙ ct−1 + i ⊙ g

Lab 3 · the cell update is one addition, with each term gated

ct is the cell state: the memory carried between steps. f, i and o are the forget, input and output gates. Each is a sigmoid, so each number sits between 0 and 1. The symbol ⊙ means multiply matching positions, one number at a time.

Three gates, three jobs

Forget decides how much of the old cell survives. Input decides how much of the new candidate is written. Output decides how much of the cell is shown to the rest of the network. All three are computed from the same pair of inputs, then applied to different things.

The cell update

ct = f ⊙ ct−1 + i ⊙ g has exactly two terms: what is kept and what is written. With ct−1 = 2, f = 0.9, i = 0.5 and g = 1, the new cell is 0.9 × 2 + 0.5 × 1 = 2.3. The old value dominates, and the new value tops it up.

Why addition beats multiplication

To train the cell, the error must travel back through this update. Its path is the factor f, not a full matrix product. With f = 0.9, twenty steps keep 0.9²⁰ ≈ 0.12 of the signal; with f = 0.99, twenty steps keep 0.82. A learnable gate can hold that path near 1.

The output gate

The cell is internal. What the next layer sees is ht = o ⊙ tanh(ct). The output gate can hide a cell that is still being filled, or reveal one that is ready. With ct = 2.3 and o = 0.5, the hidden state is 0.5 × tanh(2.3) = 0.49.

Faded example

Take ct−1 = 1.0, f = 0.9, i = 0.5, g = 0.8. Then ct = 0.9 × 1.0 + 0.5 × 0.8 = 1.30. With o = 0.5, ht = 0.5 × tanh(1.30) = 0.43. Continue the rows.

t+1: 0.9 × 1.30 + 0.5 × 0.8 = 1.17 + 0.40 = 1.57. t+2: 0.9 × 1.57 + 0.5 × (−0.8) = 1.413 − 0.400 = 1.013. A negative candidate subtracts, because the update is addition with a signed term.

The trap— f, i, o

Most common wrong mental model

"A gate is a switch: 0.9 means it forgot 10% of the memory." It feels right because the numbers look like percentages, and one step really does leak 10%.

Correction: a gate is a per-number multiplier applied at every step, so the leak compounds — 0.9²⁰ ≈ 0.12. It is also 512 separate decisions, not one. Reporting a single gate value averages 512 different ones.

The tell: a debugging note that says "the forget gate was 0.8" for a 512-wide layer. That is a mean, and a mean of 0.8 can hide half the dimensions at 0.99 and half at 0.61. Inspect the vector, not its average.

Retrieval check— f, i, o

  1. ct−1 = 2, f = 0.9, i = 0.5, g = 1. What is ct?
    Answer

    0.9 × 2 + 0.5 × 1 = 1.8 + 0.5 = 2.3. Kept first, written second.

  2. Why is an additive cell update easier to train than a plain hidden state?
    Answer

    The error's path back through c is the gate f, not a full matrix product. With f near 1 the path stays near identity, so the signal is not multiplied away at every step.
