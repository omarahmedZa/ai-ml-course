Architectures, counted · Lab 1

k²·Cin·Cout — where convolution parameters come from

You can count the weights in a convolution from its filter size and channel counts, and say why sharing makes it thousands of times smaller than a dense layer.

Where this sits

weights per filter = k² · Cin · Cout = 3² · 64 · 64 = 36,864

Lab 1 of 2 · the three factors are lit; the image size is deliberately absent

A dense layer needs one weight for every input–output pair, so its count depends on the image size. A convolution needs one small filter, reused at every position. k is the filter's side length, Cin the number of input channels, Cout the number of output channels.

A filter is a small learned window

Picture a 3×3 stencil sliding across an image, stopping at every pixel. At each stop it multiplies the nine numbers underneath by its nine weights and adds them up. The same nine numbers do the work everywhere — the stencil has no idea which pixel it is standing on.

Where the three factors come from

k² counts positions inside the window: 9 for a 3×3 filter. Cin counts the input channels read at each position. Cout counts the filters, because each output channel needs its own. Multiply: 9 × 64 × 64 = 36,864 weights. Biases add another Cout.

What sharing buys

Flatten that input and a dense layer must learn 3,211,264 × 64 = 205,520,896 weights — about 205 million, or 5,575 times the filter. Worse, it must relearn the same edge detector separately at every position. Double the image side and the dense count quadruples while the convolution stays at 36,864.

One more example

The equation fixes both channel counts at 64 and k at 3. Hold the channels there and move only the filter side: 64 × 64 = 4,096 weights for every position inside the window, so k² alone decides the total. Nothing about the image size enters the count.

5×525102,400
7×749200,704

The table shows the count growing with the square of the filter side while the two channel counts sit still, so widening k from 3 to 7 costs about 5.4 times the 36,864 of the original layer, and only the channel counts could push that number higher still.

Check the last two rows

Row 3: 9 × 128 × 128 = 147,456. Row 4: 25 × 32 × 64 = 51,200. Notice that a 5×5 filter is not automatically bigger than a 3×3 one — the channel counts decide as much as the window does.

The trap

Most common wrong mental model

"36,864 weights means the convolution is 5,575 times weaker." Parameter count is a cost, not a capacity. The dense layer spends its weights relearning the same edge at every location; the convolution spends 36,864 once and reuses them, which is a statement that location should not matter.

Correction: read the count as the price of the assumption, not as the power of the layer.

The tell: shuffle the pixels inside every image and retrain. The convolution's parameter count is unchanged, yet its advantage disappears — so the count was never the reason it worked. The sharing was.

Retrieval check

  1. A 3×3 filter takes 32 input channels to 64 output channels. How many weights?
    Answer

    9 × 32 × 64 = 18,432. Window positions first, then input channels, then output channels.

  2. Why does the convolution's weight count contain no term for image size?
    Answer

    Because the filter is reused at every position, and no weight records which position it was used at. The layer learns what to look for, not where to look.
