Tokenization, one rule at a time · Lab 1

BPE — merge the most frequent pair

You can run four BPE merges by hand, and say why 1,000 words become about 1,300 tokens.

Where this sits

repeat until the vocabulary is full: (a, b) = the most frequent adjacent pair → add ab

Lab 1 · the whole algorithm is one line, run again and again

BPE means byte-pair encoding. A symbol is any string already in the vocabulary — at the start, one character. The rule scans adjacent pairs, counts each, and replaces the winner with one new symbol. Nothing about words is consulted.

Start from characters

Training starts with the corpus characters. In the toy words below that is six symbols: b, g, h, n, p, u. Each already has an ID, so no input is ever unrepresentable.

WordCopiesAs characters
hug10h u g
pug5p u g
pun5p u n
bun5b u n
hugs5h u g s

Count, then merge

Count each adjacent pair across every copy of every word. The pair u+g appears 20 times: ten inside hug, five in pug, five in hugs. It wins, so every u followed by g becomes the single symbol ug. Two symbols become one; no character is deleted.

Then count again. Four merges, in order:

MergePairCountNew symbolExample after
1u + g20ugh ug
2h + ug15hughug
3u + n10unp un
4p + un5punpun

Merge 4 is a tie: b+un, p+ug and hug+s also count 5. A fixed rule breaks ties; the saved artifact is the order.

The merge list is the algorithm

Encoding new text means replaying these merges in this order, left to right. Counts are never taken again. The ordered list is the tokenizer's entire state, which is why two releases with the same vocabulary size can still split one word differently.

Tokens are not words

After four merges the toy corpus holds 45 tokens where it started with 95 characters and 30 words. The vocabulary is 6 characters plus 4 merges, so 10 symbols. Real English settles near 1.3 tokens per word: 1,000 words ≈ 1,300 tokens. Code and hashes run higher, because their character pairs are rarer and merge less often.

Faded example

Check the last row

pugging becomes p · ug · g · i · n · g, which is 6 tokens. Merge 3 needs a u before an n; that u was already consumed by merge 1. One character belongs to exactly one symbol.

The trap

Most common wrong mental model

"BPE finds meaningful pieces — roots, prefixes, suffixes." It feels right because merges usually land on familiar chunks, and a 50,000-token vocabulary does contain whole words.

Correction: the rule counts characters, not meaning. In a corpus where w+est is frequent, lowest can become lo + west, cutting straight through the word. That is not a bug; frequency is the only signal.

The tell: the same word splits differently in two models that both report a 50,000-token vocabulary. Vocabulary size says how many labels exist, never which strings they cover. If a pipeline checks only the size, a mismatched split passes silently.

Retrieval check

  1. In the toy corpus, why is u+g the first merge and not h+u?
    Answer

    u+g occurs 20 times; h+u occurs 15. The merge takes the largest count, regardless of where the pair sits inside a word.

  2. A nine-character word encodes to three tokens. Did the tokenizer throw away six characters?
    Answer

    No. Each token is a symbol that stands for a string. Three symbols can spell nine characters; replaying the merges recovers all nine.
