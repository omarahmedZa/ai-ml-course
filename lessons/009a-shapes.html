Equation lab · the forward pass

Shape algebra — the inner dimensions must meet

You can write the shape of every array in a two-layer forward pass, and predict the output shape before running anything.

Where this sits

ŷ = (4×2)(2×2) → (4×2) then (4×2)(2×1) → (4×1)

Lab 1 of 1 · only the shape changes are lit; the numbers inside the arrays are not the subject

Every array in a network is a rectangle of numbers with two counts: rows and columns. This lab reads those counts the way a compiler does, before any arithmetic happens.

Rows are examples, columns are features

X is 4×2: four examples, two features each. The row count is the batch, and every layer must preserve it — four examples in, four predictions out. The column count is what a layer may change, by mixing features into new ones.

The weights hold the mixing. W1 is 2×2 because it reads two features and writes two hidden values. W2 is 1×2 because it reads those two and writes one.

The rule: inner dimensions meet

To multiply A×B, the columns of A must equal the rows of B. Those two matching numbers cancel; the outer two survive as the result. So (4×2)(2×2) leaves 4×2, and (4×2)(2×1) leaves 4×1. A (4×2)(3×2) is an error, not a warning: 2 and 3 are not the same number.

The whole pass, left to right

X (4×2) times the transpose of W1 (2×2) gives z1 at 4×2. The bend φ changes no shape. Then W2 transposed is 2×1, so (4×2)(2×1) gives 4×1. The four rows survive every step; only the columns move 2 → 2 → 1.

Where the bias fits

b1 has length 2 and is added to a 4×2 array. It is repeated down all four rows, which is called broadcasting. That is the intended behaviour, and it is also why a bias of the wrong length can run silently: the addition succeeds, and the shape rule alone will not catch it.

Check the missing shape

A1 is 8×2. The batch of 8 meets W1's inner 2, and the hidden count of 2 survives; then (8×2)(2×1) gives 8×1. Only the leading number moved.

The trap

Most common wrong mental model

"If the code runs, the shapes are right." It feels right because shape errors are the ones that do raise an exception, so a silent run seems like confirmation.

Correction: broadcasting and square weights make wrong code run. A 2×2 weight applied on the wrong side of the input still produces a number — just not the one you meant.

The tell: write the four shapes on paper before running. If the output is 4×2 when you expected 2×4, you have a transpose, not a mistake in the arithmetic.

Retrieval check

  1. X is 4×2 and W1 is 3×2. What is the shape of XW1T?
    Answer

    4×3. The inner 2s meet and cancel; 4 rows and 3 hidden units survive.

  2. A batch of 32 examples, two features, one output. What shape is the prediction?
    Answer

    32×1. (32×2)(2×1). The batch never shrinks — one prediction per row.
