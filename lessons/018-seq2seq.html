Seq2seq & encoder–decoder

You can explain translation as encode-then-decode, and state the alignment problem attention solves.

Why this matters

Encoder–decoder is the shape of every modern generative model: summarisation, translation, speech-to-text, and the chat model you are talking to. The decoder is the same object in all of them.

The one core idea

Read the input into a state, then generate the output one token at a time conditioned on that state. The weakness is structural: everything the decoder knows must fit through one fixed vector.

How it actually works

  • Encoder: an RNN consumes x₁…x_n and returns a final hidden state h_n. No output, just a summary.
  • Decoder: initialised with h_n, emits y₁…y_m autoregressively. Each step's output is fed back as the next input.
  • Teacher forcing: during training, feed the true previous token instead of the model's prediction. Speeds convergence, but creates a train/test mismatch.
  • Exposure bias: at inference the model consumes its own errors, so one bad token can derail the rest. Mitigations: scheduled sampling, beam search.
  • The bottleneck: a 30-token sentence and a 3-token sentence both compress to the same 512 numbers. Early words are the first to be overwritten.
  • Attention (topic 26) removes the bottleneck: the decoder looks back at all encoder states, not just the last one.
encoder: (x₁…x_n) → h_n decoder: (h_n, y₁…y_{t−1}) → y_t

2. Why the decoder is slow

Generating m tokens requires m sequential forward passes: step t needs y_{t−1}. Training is parallel (teacher forcing supplies all previous tokens at once); inference is not. This asymmetry is why generation latency scales with output length.

The trap

Most common wrong mental model

"Seq2seq means transformer." The original 2014 seq2seq was two LSTMs. The transformer is a different implementation of the same encoder–decoder contract, with attention replacing recurrence.

Second trap: assuming teacher forcing is also used at inference. It cannot be — the true next token does not exist yet. That gap between training and deployment is a real source of degradation.

Retrieval check

  1. Why does a longer input sentence hurt a vanilla seq2seq model more than a shorter one?
    Answer

    All information must pass through one fixed-size vector. Longer inputs mean more content per dimension, so early tokens are overwritten by later ones.

  2. What is teacher forcing, and what problem does it create?
    Answer

    Feeding the ground-truth previous token during training. It makes training fast and stable, but the model never practises recovering from its own mistakes — exposure bias.

  3. How does attention change the decoder's access to the input?
    Answer

    Instead of one summary vector, the decoder can query every encoder state and weight them per output step. The bottleneck becomes a soft lookup.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
rng = np.random.default_rng(0)
def encode(tokens, dim=8):
    """Toy encoder: mean of token vectors, i.e. a fixed-size summary."""
    return rng.normal(size=(len(tokens), dim)).mean(axis=0)
for n in (4, 16, 64):
    s = encode(["w"] * n)
