Tokenization: text → integers

You can explain vocabularies, subwords, OOV, and why token count is not word count.

Why this matters

Context windows, API bills, and truncation bugs are all counted in tokens, not words. Every number you read about an LLM — 128k context, $3 per million — is in this unit.

The one core idea

A model needs integers, so text is split into tokens from a fixed vocabulary. Splitting on words fails on the long tail; splitting on characters loses meaning. Subword tokenisation splits the difference.

How it actually works

  • Vocabulary = fixed list of tokens, each mapped to an integer ID. Typical sizes: 32k–100k for modern LLMs.
  • Word-level: clean, but any unseen word becomes <UNK> — the out-of-vocabulary problem. Rare names, typos, and morphology all break.
  • Character-level: no OOV ever, but sequences get 4–5× longer and each token carries little meaning.
  • BPE / WordPiece: start from characters, repeatedly merge the most frequent adjacent pair. Frequent words become one token; rare words become a few meaningful pieces.
  • Special tokens: <bos>, <eos>, <pad>, <mask> — structural signals, not content.
  • Context window is measured in tokens, and so is cost. A token is roughly 4 characters of English (~0.75 words).
"unbelievable" → ["un", "believ", "able"] → [371, 7892, 531]

Worked example

1. Why 1,000 words is not 1,000 tokens

TextWordsTokens (approx.)
Plain English prose1,0001,300
Code1,0001,700
Base64 blob / hashes1,0004,000+

Punctuation, indentation and rare identifiers fragment into many tokens. A 4,000-token budget that fits your prose will silently truncate a code file.

2. Where the boundary falls

Byte-pair merges are frequency-driven, so common words are single tokens and rare ones fragment: "the" → 1 token; "antidisestablishmentarianism" → 7. The same word with a leading space ("the" vs " the") can be a different token, because spacing is part of the merge history.

The trap

Most common wrong mental model

"Tokens are words." They are not. Counting words to check a context limit under-counts by 30% on prose and far more on code. Truncating by characters can slice a token in half, producing a different token than either half.

Second trap: assuming a model can count letters or reverse words reliably. It never sees characters — it sees IDs. Asking "how many r's in strawberry" is a question about a representation the model does not have.

Retrieval check

  1. Why does word-level tokenisation fail on medical text?
    Answer

    The vocabulary cannot contain every drug name and abbreviation. Unseen terms collapse to <UNK>, erasing distinctions the model needs — including negation and dosage.

  2. A 128k-token context holds roughly how many English words? What about lines of code?
    Answer

    Roughly 95,000 words of prose (÷1.3), but far fewer lines of code — code runs nearer 1.7 tokens per word, and identifiers fragment further.

  3. What does BPE actually merge, and in what order?
    Answer

    The most frequent adjacent pair of symbols, repeatedly, starting from characters. Frequency decides order, which is why frequent words end up as single tokens.
