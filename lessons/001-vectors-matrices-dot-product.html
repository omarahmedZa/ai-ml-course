Vectors, matrices, and the dot product

You can read any score function as a dot product, and check its shapes mechanically.

Why this matters

Every model in this course eventually computes one number from two lists of numbers. A linear layer does it. An embedding lookup does it. An attention score does it. A Q-value does it. The notation changes; the operation does not.

That matters for two practical reasons. In an exam, a shape question is free marks: "A is 5×3 and x has four entries — what happens?" has one correct answer and no ambiguity. In your project, most failures in the first hour are not conceptual; they are a matrix with the wrong orientation, and Python reports a shape error several lines away from the cause. If you can see the dot product underneath, both problems become mechanical rather than mysterious.

The one core idea

A score measures alignment between two vectors: what the input is (x) and what the model is looking for (w). The dot product adds up, feature by feature, how much they agree.

In one line: each feature casts a vote, the weight says how much that vote counts, and the dot product adds the votes. With x = [2, 1] and w = [3, −1], feature 1 votes +6, feature 2 votes −1, and the total is 5.

How it actually works

Take it in seven parts. Each part is one idea, and each builds on the one before it.

Part 1 — A vector is a row of features

A vector is n numbers kept together as one object. In machine learning it is almost always one data point: a house might be [3 bedrooms, 1.5 bathrooms, 120 m²]. The order is arbitrary but fixed — position 1 always means bedrooms. If you reorder the features, you must reorder the weights identically, or the model silently compares the wrong things.

Part 2 — The dot product multiplies matching positions, then adds

x · w = x₁w₁ + x₂w₂ + … + xₙwₙ

Each term is one feature's contribution: how strongly the feature is present (xᵢ) times how much the model cares about it (wᵢ). A large feature with a weight near zero contributes almost nothing; a small feature with a huge weight can dominate. Why this shape of formula? Because it is the simplest function that is linear in the input and treats each feature independently — no interaction terms, no thresholds, just weighted agreement.

Part 3 — The sign is a decision, the size is confidence

Positive means x lies on w's side of the boundary. Zero means the two are perpendicular: the input has nothing the model is looking for. Negative means it points the other way. In a classifier, the boundary is exactly w·x + b = 0, so the sign answers "which class?" and the distance from zero answers "how sure?". This is why a score of 0.2 and a score of 20 can give the same label but very different confidence.

Part 4 — Length inflates the score

Geometrically, x·w = ‖x‖ ‖w‖ cos θ, where ‖·‖ is the length of the arrow and θ is the angle between them. Two consequences follow. First, the score grows if you simply make x longer — double every feature and the score doubles, even though the direction, and therefore the meaning, is unchanged. Second, the only part that carries direction is cos θ.

Part 5 — Cosine removes the length

Divide the dot product by both lengths: cos θ = (x·w) / (‖x‖ ‖w‖). The result is between −1 and 1 and depends only on direction. Use it whenever length is noise — a long document, a frequently occurring word, an embedding whose norm drifted during training (topic 16). Use the raw dot product when length is real information: a price, a count, a dose.

Part 6 — A matrix is a stack of questions

A matrix is just several weight vectors stacked as rows. Multiplying W by x runs one dot product per row, so a 2×3 matrix returns two scores. The shape rule is unforgiving: (m×n)(n×k) → (m×k). The inner dimensions must be equal; nothing else is negotiable. A 5×3 matrix needs a 3-vector and returns 5 numbers.

Part 7 — A neuron is this plus a threshold

A single neuron computes w·x + b and then applies a bend such as ReLU. The bias b shifts when the neuron fires; it does not change what the neuron looks for. That is the whole object you will meet again in topic 8 — the rest of deep learning is stacking it.

TermPlain meaning
VectorAn ordered list of numbers: one data point, or one arrow.

Worked example

1. One score, two features

x = [2, 1], w = [3, −1], b = −1. Do every multiplication explicitly; skipping them is how sign errors survive.

StepArithmeticRunning total
Feature 12 × 3+6
Feature 21 × (−1)−1 → total 5
Add bias5 + (−1)4

What to notice. The second feature reduced the score. That is not a bug: the model believes more of feature 2 is evidence against. If the feature were absent (x₂ = 0), it would contribute exactly 0 — absence is neutral, not negative. And if you change only the model, to w = [3, 1], the score becomes 6: same data, different question, different answer.

2. Two questions at once

W = [[1, 0, −1], [0, 2, 1]], x = [1, 2, 3]. Each row is its own weight vector.

RowTerm-by-termScore
Row 11(1) + 0(2) + (−1)(3) = 1 + 0 − 3−2
Row 20(1) + 2(2) + 1(3) = 0 + 4 + 37

What to notice. The zero weights are not decorative: row 1 ignores feature 2 entirely, so no value of x₂ could change its score. Row 2 ignores feature 1. That is how a matrix encodes "different questions for different outputs".

3. From one example to a batch, and why the transpose appears

Put four examples as rows: X is 4×3. To get four examples × two scores you compute X Wᵀ:

(4×3) · (3×2) = (4×2)

The transpose exists for one reason: the inner dimensions must match. X has 3 columns; Wᵀ has 3 rows. The output has one row per example and one column per score, which is exactly the layout every dataset expects. If you write W Xᵀ instead you get (2×3)(3×4) = (2×4) — numerically valid, semantically transposed, and usually the bug behind "my labels and predictions don't line up".

The trap

Most common wrong mental model

"A bigger dot product means more similar." It feels right because the dot product is a similarity measure — for vectors of equal length. Once lengths differ, the score mixes two things: direction and magnitude.

Concretely: q = [1, 0]. Document a = [50, 0] scores 50 with cosine 1.0. Document b = [1, 0.1] scores 1 with cosine 0.995. Both point almost exactly along the query; the dot product prefers the longer one, which has nothing to do with relevance.

Correction: decide what length means before choosing a metric. Meaningful length (price, count, dose) → raw dot product. Noise length (document length, word frequency, embedding norm) → normalize first, which is cosine.

The tell: if duplicating a document's text — doubling every number in its vector — makes it rank higher for the same query, you are scoring length, not meaning. The second tell is a shape that runs but produces numbers 10× too large: someone multiplied elementwise when they meant a matrix product. A matrix–vector product is never elementwise; each output cell is one full row·column dot product.

Retrieval check

  1. Compute [1, −2, 3] · [4, 0, −1].
    Answer

    4 + 0 + (−3) = 1. Positive but small: nearly perpendicular, so only weak agreement.

  2. A is 5×3. You want Ax. How long must x be, and how long is the result?
    Answer

    x must have 3 entries; the result has 5. Rule: (5×3)(3×1) → (5×1). A 4-entry x makes the expression undefined, not merely wrong.

  3. You retrieve docs for q = [1, 0]. Doc A = [50, 0]: dot 50, cosine 1.0. Doc B = [1, 0.1]: dot 1, cosine 0.995. Which ranks first, and why?
    Answer

    By cosine they are effectively tied, and A is marginally better aligned. By raw dot product A wins 50-to-1 — for a reason that has nothing to do with relevance. When embedding norms vary for arbitrary reasons, normalize; otherwise the longest document wins every query.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. Sections, plots, sliders and line-by-line notes — run the cells in order, then change one number and rerun.

import numpy as np
x, w, b = np.array([2., 1.]), np.array([3., -1.]), -1.
print("x·w =", x @ w, "| score =", x @ w + b)
q = np.array([1., 0.])
for name, v in [("A", np.array([50., 0.])), ("B", np.array([1., .1]))]:
    cos = (q @ v) / (np.linalg.norm(q) * np.linalg.norm(v))
    print(f"{name}: dot={q @ v:6.2f}  cosine={cos:.3f}")

Extra practice

Two harder questions. Three attempts each — the answer unlocks only after the third miss. Correct on the first try is worth 2 points, later 1, revealed 0.
