Vectors, matrices, and the dot product

You can read any score function as a dot product, and check its shapes mechanically.

Why this matters

Every model in this course is a dot product in disguise: a linear layer, an embedding lookup, an attention score, a Q-value. Make dot products and shape rules automatic, and the notation stops eating your working memory.

The one core idea

A score is a measurement of alignment between two vectors: what the input is (x), and what the model is looking for (w). Training is nothing more than choosing w so that the right inputs align.

How it actually works

  • Vector = n numbers treated as one object: one data point with n features, or an arrow from the origin.
  • Dot product = multiply matching positions, then add.
x · w = x₁w₁ + x₂w₂ + … + xₙwₙ

Three equivalent readings of that number:

ReadingWhat it tells you
Sum of per-feature agreementsFeature 1 wants +3, you have +2 → contribution +6
‖x‖ ‖w‖ cos θHow parallel the two arrows are, scaled by their lengths
Projection × lengthHow far x's shadow reaches along w
  • Sign is the message. Positive → same half-space as w. Zero → perpendicular, nothing in common. Negative → pointing away.
  • Cosine similarity divides the lengths out: cos θ = (x·w) / (‖x‖‖w‖), range −1 to 1. Use it when magnitude is noise — exactly the case for embeddings (topic 16).
  • Matrix = m row-vectors stacked; Wx is m dot products at once. Shape rule (m×n)(n×k) → (m×k): inner dimensions must match.
  • A neuron before its nonlinearity is w·x + b. The bias shifts the threshold; it does not rotate w.

Worked example

1. One score, three features

x = [2, 1], w = [3, −1], b = −1:

StepValue
Feature 12 × 3 = 6
Feature 21 × (−1) = −1
Dot product5
Plus bias5 + (−1) = 4

Positive, so x sits on w's side. Flip the second weight to w = [3, 1] and the score is 6. x never changed; the model changed what it looked for.

2. A matrix, then a batch

Two output scores, three features each:

W = [[1, 0, −1], [0, 2, 1]] · x = [1, 2, 3]
OutputDot productResult
Score 1 (row 1)1(1) + 0(2) + (−1)(3)−2
Score 2 (row 2)0(1) + 2(2) + 1(3)7

Stack four examples: X is 4×3, and X Wᵀ gives (4×3)(3×2) → (4×2) — four examples, two scores. The transpose is what makes inner dimensions agree; that habit catches most shape bugs.

The trap

Most common wrong mental model

"A bigger dot product means more similar." False — it mixes direction with length. With q = [1, 0], both a = [50, 0] and b = [1, 0.1] point along q, but a scores 50 and b scores 1. The dot product picked the long vector.

Correction: ask what length means. Meaningful length (price, count) → raw dot product. Noise length (document length, embedding norm) → normalize, i.e. cosine.

Related trap, same root: a matrix–vector product is not elementwise — each output cell is one row·column dot product, and Wx ≠ xW. Let the shapes decide which you meant.

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. Compute [1, −2, 3] · [4, 0, −1].
    Answer

    4 + 0 + (−3) = 1. Positive but small: nearly perpendicular, so only weak agreement.

  2. A is 5×3. You want Ax. How long must x be, and how long is the result?
    Answer

    x must have 3 entries; the result has 5. Rule: (5×3)(3×1) → (5×1). A 4-entry x makes the expression undefined, not merely wrong.

  3. You retrieve docs for q = [1, 0]. Doc A = [50, 0]: dot 50, cosine 1.0. Doc B = [1, 0.1]: dot 1, cosine 0.995. Which ranks first, and why?
    Answer

    By cosine they are effectively tied, and A is marginally better aligned. By raw dot product A wins 50-to-1 — for a reason that has nothing to do with relevance. When embedding norms vary for arbitrary reasons, normalize; otherwise the longest document wins every query.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
x, w, b = np.array([2., 1.]), np.array([3., -1.]), -1.
print("x·w =", x @ w, "| score =", x @ w + b)
q = np.array([1., 0.])
for name, v in [("A", np.array([50., 0.])), ("B", np.array([1., .1]))]:
    cos = (q @ v) / (np.linalg.norm(q) * np.linalg.norm(v))
    print(f"{name}: dot={q @ v:6.2f}  cosine={cos:.3f}")

Extra practice

Two harder questions. Three attempts each — the answer unlocks only after the third miss. Correct on the first try is worth 2 points, later 1, revealed 0.
