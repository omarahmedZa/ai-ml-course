Backpropagation

You can apply the chain rule to a small graph and say what each gradient means.

Why this matters

Every "the model won't learn" bug is a gradient bug: wrong sign, vanished, exploded, or detached from the graph. Backprop is the one mechanism you must be able to inspect rather than trust.

An exam will ask you to differentiate a small graph by hand, and there is no way to bluff it: either the local slopes are multiplied in the right order or the number is wrong. In a project the same skill explains a frozen loss — a ReLU that zeroed its own gradient, a tensor cut out of the graph with .detach(), or a learning rate that turned a slope of −12 into a jump past the minimum. All three look identical from outside: the curve is flat.

The one core idea

Blame flows backwards through the graph. Each operation knows its own local slope — how much its output moves when its input moves by one — and the loss hands back a single number. A node multiplies what it received by its own slope and passes the product to its inputs.

In one line: upstream times local, added at every fork. For L = (3w)² at w = 2, the outside slope is 2(6) = 12, the inside slope is 3, and the product is 36.

How it actually works

Part 1 — Write the graph, not the formula

Every operation becomes a node: a multiply, an add, a ReLU, a matrix product, the loss. Values flow forward along the edges, and L = (wx + b − y)² is four nodes — multiply, add, subtract, square. Reading the same expression as a graph is what removes the ambiguity of "which derivative first". Why this part exists: each node then has exactly one place to send its result, so the backward order stops being a judgement call.

Part 2 — Forward caches what backward needs

While computing forward, each node stores its inputs and its output: the multiply node keeps x, the subtract node keeps z − y. Nothing is recomputed on the way back. The stored x = 2 is the whole reason the gradient for w costs one multiplication. Why this part exists: without the cache, backward would redo a forward pass at every node, and training would cost depth-squared.

Part 3 — Seed the sweep with 1

Start at the loss and set ∂L/∂L = 1, because the loss changes one-for-one with itself. This is the only number supplied by hand; everything after it is multiplication by local slopes. Why this part exists: without a seed the chain has no starting quantity, and every gradient downstream would be zero times something.

Part 4 — Multiply by the local derivative

Each node applies one rule: u² gives 2u, an add passes the gradient through unchanged, a multiply by a constant scales it, ReLU passes it only where z > 0. Walking back from L to w in the example above accumulates 2(z − y)·x. Why this part exists: this is the chain rule, the only way a slope measured at the loss becomes a slope at a weight nine operations away.

Part 5 — Forks add their contributions

When one value feeds two branches, both send a gradient back and the node sums them. A value reached by two paths has a total derivative equal to the sum over paths, never the product. Why this part exists: dropping one branch silently halves the gradient, which behaves exactly like halving the learning rate for those weights alone.

Part 6 — One sweep prices every parameter

Reverse mode costs roughly one extra forward pass in total, regardless of parameter count. Finite differences — nudge one weight, remeasure the loss — need two forward passes per parameter: for 1,000,000 weights that is 2,000,000 passes against about 2. Why this part exists: the ratio is why deep learning is practical; the naive alternative is a million times slower for the same answer.

Part 7 — Sign says which way, size says how far

A gradient is a slope: positive means raising the weight raises the loss, so you subtract. With ∂L/∂w = −12 and η = 0.1, the step is w ← w − 0.1(−12) = w + 1.2. Why this part exists: the minus sign is the whole of gradient descent; write it as a plus and every step climbs the loss on purpose.

Worked example

1. One linear unit, by hand

z = wx + b and L = (z − y)², with x = 2, w = 3, b = 1, y = 10. The forward column comes first, then the backward column.

QuantityDerivationValue
z3(2) + 17
L(7 − 10)²9
∂L/∂z2(7 − 10)−6
∂L/∂w∂L/∂z · x = −6 · 2−12
∂L/∂b∂L/∂z · 1 = −6 · 1−6

With η = 0.1: w = 3 − 0.1(−12) = 4.2 and b = 1 − 0.1(−6) = 1.6. Feed forward again: 4.2(2) + 1.6 = 10, loss 0.

What to notice. Both gradients are negative, so both parameters increase, and the prediction rises from 7 to 10 in one step. That exactness is a property of this quadratic, not of training in general: the gradient is a straight-line approximation, and a curved loss would land nearby rather than on the target. The factor x = 2 is why w moves twice as far as b — the same slope, scaled by the input that multiplies it.

2. Reading a real graph

L = (a·b + c)² with a = 2, b = 3, c = 1. The inner value u = ab + c gets one gradient; the three inputs split it.

Apply one step with η = 0.01: a = 2 − 0.42 = 1.58, b = 3 − 0.28 = 2.72, c = 1 − 0.14 = 0.86. Then u = 1.58(2.72) + 0.86 = 5.1576 and L = 26.60, down from 49.

What to notice. One backward sweep produced three gradients from a single incoming value of 14: each input multiplies that value by its own local slope. The largest gradient belongs to a, and that is not a statement about importance — it is b = 3 sitting in the local slope, so a has three times more leverage per unit than c does.

3. Checking a gradient with a small nudge

Take the first example and raise w by 0.001, leaving x, b and y alone. A true slope of −12 predicts a loss drop of about 0.012.

What to notice. The check is a finite difference, so it is always slightly off and always the same sign. Use it on one weight when a hand-derived gradient and the library disagree; a large gap means a missing term, a wrong sign, or a tensor that was detached before the graph noticed it.

The trap

Most common wrong mental model

"A big gradient means an important parameter." It feels right because the update is proportional to the gradient, so the big ones visibly move first.

Correction: a gradient is a local slope at the current weights, not a property of the parameter. It depends on the input scale, the loss scale and everything downstream, and it is recomputed from scratch every step. The same weight can have a gradient of −12 at initialisation and −0.01 one update later.

The tell: keep the prediction identical while multiplying one input by 100 and dividing its weight by 100 — the loss does not move, but that weight's gradient grows 100×. A quantity that changes when units change is a slope, not an importance score. The second tell is a ranking — "this feature matters least because its gradient is smallest" — that reorders when you standardise the columns.

Retrieval check

  1. L = (3w)². What is dL/dw at w = 2?
    Answer

    L = 9w², so dL/dw = 18w = 36. Via the chain rule: 2(3w)·3 = 18w. Same answer; the chain rule is not optional bookkeeping, it is the derivative.

  2. A value feeds two branches of the graph. How do the two gradients combine?
    Answer

    They add. Total derivative = sum of contributions from every path. This is exactly why accumulating gradients across micro-batches is mathematically valid.

  3. Why is backprop cheaper than finite differences for 1M parameters?
    Answer

    Finite differences need two forward passes per parameter — about 2M passes. Backprop gets every gradient in one backward pass, roughly the cost of one forward pass.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
x, w, b, y = 2., 3., 1., 10.
pred = w * x + b
loss = (pred - y) ** 2
d_pred = 2 * (pred - y)
d_w, d_b = d_pred * x, d_pred
print(f"pred={pred} loss={loss} dL/dw={d_w} dL/db={d_b}")
