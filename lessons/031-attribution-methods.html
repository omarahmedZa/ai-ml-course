Attribution methods: what each one computes

You can explain what saliency, LIME and SHAP compute, and their failure modes.

Why this matters

Four attribution methods look at one prediction and return four different lists of important features. All four are defensible, and they disagree. Knowing the definition behind each is the difference between citing an attribution and being fooled by one, because the number on the chart is only as good as the procedure that produced it.

A credit team shipped LIME explanations with a fixed seed. Auditing six months later with the library's default seed, the top feature moved from "missed payments" to "account age" for the same applicant and the same model. Nothing about the decision had changed; the random sample under the explainer had. That is the failure this topic prevents: four definitions of "important", and only one that must add up to the prediction.

The one core idea

Every attribution method apportions one output among the inputs. They differ in what counts as evidence: the slope right here, the average slope along a path from a neutral input, the weights of a simple model fitted nearby, or the average gain from adding a feature to a coalition. Same question in English, four different mathematical answers.

In one line: saliency asks about a nudge, integrated gradients about a journey, LIME about a neighbourhood, and Shapley about a coalition. With two features where v({1}) = 0.6, v({2}) = 0.4 and v({1,2}) = 1.0, Shapley returns 0.6 and 0.4 — and they sum to exactly 1.0, the whole output.

How it actually works

Seven parts, from one number to four procedures.

Part 1 — Credit is a gap, so it needs a zero point

A feature's credit is the output with the feature minus the output without it. With no zero point there is no gap to measure. In the Shapley example below, feature 1 earns 0.6 only because v({1}) = 0.6 is read against v(∅) = 0.

Why this part exists: shift the zero point and every number shifts; two teams can compare charts that answer different questions.

Part 2 — Saliency reads the slope at one point

Saliency is ∂f/∂xᵢ at the input: how fast the score moves if you nudge feature i by a hair. It costs one backward pass, which is why it is the default in vision pipelines. It describes the tangent, never the feature's necessity.

Why this part exists: it is the cheapest attribution there is; one backward pass is sometimes all a live system can afford.

Part 3 — Saturation makes that slope lie

A ReLU or sigmoid can be flat exactly where the input sits, so the gradient reads 0 while the feature still drives the output. A sigmoid's derivative at input 5 is 0.0066, about 1/38 of its value at 0, which is 0.25. The map looks confident and is blind in that region.

Why this part exists: without this, you read a blank patch as "irrelevant" when it only means "saturated".

Part 4 — Integrated gradients averages the slope along a path

Integrated gradients walks a straight line from a baseline input x′ to the real input x, averages the gradient along that line, and multiplies by the distance travelled. It costs 20–300 passes instead of one. Completeness holds by construction: the attributions sum exactly to f(x) − f(x′).

Why this part exists: averaging repairs saturation, and completeness gives an auditor an identity to check — the parts must add up to the whole.

Part 5 — LIME fits a straight line to a neighbourhood

LIME perturbs the input hundreds of times, queries the black box on each perturbed copy, and fits a sparse linear model weighted by distance from the original. Those coefficients are the explanation. The linear model describes the neighbourhood it was fitted in, not the model.

Why this part exists: it needs no gradients and no internals, so it works on any model behind an API — often the only option for a vendor system.

Part 6 — Shapley averages marginal gains over orderings

Treat features as players in a coalition. Add them in some order, recording what each one added when it joined; average that gain over every possible order. Two features give 2 orderings, ten give 10! = 3,628,800. That average is the Shapley value.

φᵢ = Σ_{S ⊆ F\{i}} |S|!(|F|−|S|−1)! / |F|! · [ v(S ∪ {i}) − v(S) ]

Why this part exists: order matters — a duplicate adds nothing when it joins second — so averaging is the only way to give each feature one fair number.

Part 7 — The axioms decide what you may cite

Shapley is the unique attribution satisfying four properties: efficiency (the parts sum to the whole), symmetry (identical players get equal credit), dummy (useless players get zero) and additivity. Those four make SHAP the default in regulated work; exact computation is exponential without sampling.

Why this part exists: in a challenge, "this is the only method satisfying the properties we promised" ends the argument; "it looked sensible" does not.

Worked example

1. Shapley by hand, two features

v(∅) = 0, v({1}) = 0.6, v({2}) = 0.4, v({1,2}) = 1.0. Two features mean two orderings, each weighted 1/2.

FeatureOrder 1 → 2Order 2 → 1Average φ
10.6 − 0 = 0.61.0 − 0.4 = 0.60.6
21.0 − 0.6 = 0.40.4 − 0 = 0.40.4

What to notice. The two columns agree because this game happens to be additive: 0.6 + 0.4 = 1.0. Change one value to v({1,2}) = 0.9 and they stop agreeing — feature 1 gets (0.6 + 0.5)/2 = 0.55 and feature 2 gets (0.3 + 0.4)/2 = 0.35. The sum is still 0.9, which is efficiency doing its job: the parts equal f(x) − f(∅).

2. Saliency against integrated gradients

The smallest model that shows the difference is f(x) = x², with baseline x′ = 0 and input x = 3.

MethodArithmeticAttribution
Saliency2x at x = 36
Integrated gradients(3 − 0) × average of 6t for t in [0, 1] = 3 × 39
True difference f(3) − f(0)9 − 09

What to notice. The gradient is correct as a slope and wrong as an attribution: it reports 6 where the feature is worth 9, an understatement of one third. Integrated gradients recovers the full gap because it averages the slope over the whole journey, including the flat region near zero. On a linear model the two coincide, which is why textbook examples hide this.

3. LIME under two seeds

One input, one model, one explainer, two random seeds. Coefficients as reported:

FeatureSeed 0Seed 7
Missed payments0.420.05
Account age0.110.38

What to notice. The top feature flips, and the first feature's weight falls by a factor of 0.42 / 0.05 = 8.4. Even the total changes, 0.62 to 0.55, because a different surrogate was fitted. Run the explainer twice before publishing: if the ranking moves, it is sampling noise wearing a coefficient's confidence.

The trap

Most common wrong mental model

"SHAP values are causal." It feels right because Shapley comes from cooperative game theory, where the players really do produce the payout together. But the "payout" here is a model's output, and the value function is a conditional expectation under the training distribution — never an intervention in the world.

Two perfectly correlated columns each get about half the credit, though a domain expert would name one driver. Both are redundant evidence; the arithmetic cannot tell them apart.

Correction: read every attribution as "how much of this output this input explains, given the others as measured". If a correlated split is unacceptable, drop one column or use a conditional variant — but never turn a SHAP number into a claim about intervening in the world.

Second trap: trusting LIME because it is model-agnostic. Agnostic buys coverage, not stability; seed 2 above is the counter-example.

The tell: a sentence with no zero point in it — "income is the most important feature" — or numbers that cannot be made to sum to anything. Ask which baseline the value is measured from, then re-run the explainer with a different seed and a slightly perturbed input. If the ranking survives both, you have evidence; if it moves, you have a screenshot.

Retrieval check

  1. Why does integrated gradients need a baseline, and what breaks if you choose a bad one?
    Answer

    It integrates gradients along a path from that baseline to the input. A baseline that is off-manifold (e.g. all-black where black is meaningful) produces attributions for a path the model never encounters.

  2. Which property do Shapley values satisfy that saliency does not?
    Answer

    Efficiency/completeness: attributions sum exactly to the difference between the prediction and the baseline. Saliency has no such conservation law.

  3. Two features are perfectly correlated. What does SHAP do, and why is that a problem?
    Answer

    It splits credit between them roughly evenly, because each is marginally redundant given the other. A domain expert would name one as the driver; SHAP reports both as half-important.
