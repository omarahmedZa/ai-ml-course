Attribution methods: what each one computes

You can explain what saliency, LIME and SHAP compute, and their failure modes.

Why this matters

Four methods produce four different "explanations" of the same prediction. Knowing the definition behind each is the difference between citing an attribution and being fooled by one.

The one core idea

Every attribution method apportions the output among input features — but they differ in what count as evidence: a local gradient, a local surrogate, or an average over all feature orderings.

How it actually works

MethodComputesCostWeakness
Saliency∂f/∂xᵢ at the input1 backward passSaturates; noisy; not class-complete
Integrated gradientsPath integral of gradients from a baseline to x20–300 passesBaseline choice changes the answer
LIMEFit a sparse linear model to perturbations near xHundreds of queriesUnstable; sampling near a point is ill-defined
SHAPShapley values: average marginal contribution over all feature subsetsExponential exact; sampled in practiceAssumes feature independence unless corrected
  • Saliency answers: "if I nudge this pixel, how fast does the score move?" It is local and instantaneous — flat regions (saturated ReLU, sigmoid) report zero importance even when the feature matters.
  • Integrated gradients fixes saturation by averaging gradients along a straight line from a neutral baseline. Completeness holds: attributions sum to f(x) − f(baseline).
  • LIME is model-agnostic: perturb, query, fit a simple surrogate. The surrogate explains the surrogate, not the model — and different random seeds give different answers.
  • Shapley is the unique attribution satisfying efficiency, symmetry, dummy and additivity. Those axioms are why SHAP is the default in regulated settings.
φᵢ = Σ_{S ⊆ F\{i}} |S|!(|F|−|S|−1)! / |F|! · [ v(S ∪ {i}) − v(S) ]

Worked example

1. Shapley by hand, two features

v(∅) = 0, v({1}) = 0.6, v({2}) = 0.4, v({1,2}) = 1.0.

FeatureOrder 1→2Order 2→1Average φ
10.6 − 0 = 0.61.0 − 0.4 = 0.60.6
21.0 − 0.6 = 0.40.4 − 0 = 0.40.4

They sum to 1.0, the full output. That efficiency property is what makes SHAP auditable: the parts add up to the whole.

2. When saliency lies

A pixel has gradient 0 because the ReLU is off, yet removing it changes the prediction. The gradient is a local slope, not a measure of necessity. Integrated gradients or an occlusion test would catch it; raw saliency will not.

The trap

Most common wrong mental model

"SHAP values are causal." They are conditional expectations under the model's input distribution. Correlated features split credit arbitrarily — two identical columns each get half, and neither is "the cause".

Second trap: treating LIME's stability as guaranteed. Re-run it with a different seed and the top feature can change. If an explanation is not stable, it is not evidence.

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. Why does integrated gradients need a baseline, and what breaks if you choose a bad one?
    Answer

    It integrates gradients along a path from that baseline to the input. A baseline that is off-manifold (e.g. all-black where black is meaningful) produces attributions for a path the model never encounters.

  2. Which property do Shapley values satisfy that saliency does not?
    Answer

    Efficiency/completeness: attributions sum exactly to the difference between the prediction and the baseline. Saliency has no such conservation law.

  3. Two features are perfectly correlated. What does SHAP do, and why is that a problem?
    Answer

    It splits credit between them roughly evenly, because each is marginally redundant given the other. A domain expert would name one as the driver; SHAP reports both as half-important.
