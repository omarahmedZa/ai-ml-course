Layers and the forward pass

You can trace shapes and values through a two-layer network by hand.

Why this matters

A forward pass is the whole journey from input to loss: every matrix multiply, every bias, every bend, in order. Trace one on paper and debugging stops being guesswork.

Shape mistakes are the most common failure in a first network, and they are cheap to prevent. An exam question — "layer 1 has 10 units, layer 2 has 5, batch of 32: what shape is W²?" — takes ten seconds with the rule and cannot be guessed without it. In a project the same gap appears as mat1 and mat2 shapes cannot be multiplied, reported on a line far from the cause, after a twenty-minute run has already died.

The one core idea

A forward pass is a relay of two moves, repeated: a layer rotates and stretches its input, then a bend curves each number separately. The rotation is learned; the bend is fixed. That is the entire architecture.

In one line: affine (matrix plus bias), bend, affine, bend. On one example, 2 → 2 → 1 runs (2×2)(2×1) → (2×1) then (1×2)(2×1) → (1×1). On a batch of 32 the same steps run as (32×2)(2×2) → (32×2) then (32×2)(2×1) → (32×1), and the 32 is never touched.

How it actually works

Part 1 — One layer is one affine map

Each layer computes z = Wa + b: a matrix product with the previous layer's output, then a bias added. W holds the weights and a is the incoming activations. For a 3-unit layer reading 4 numbers, W is 3×4, and the product mixes all four inputs into each of the three outputs. Why this part exists: the mixing is where learning happens; without a matrix, each output could only ever see one input.

Part 2 — Two names, one vector

The linear step produces z, the pre-activation, and the bend produces a = φ(z), the activation. Same shape, different stage: z is what the weights computed, a is what the next layer receives. With ReLU, z = [−0.4, 2.1] becomes a = [0, 2.1]. Why this part exists: every bug report about a "dead layer" is a claim about z, so keeping the two names apart keeps the diagnosis honest.

Part 3 — The shape rule

A layer with n_in inputs and n_out units has W of shape n_out × n_in and b of length n_out. The rule is forced by the multiplication — inner dimensions must match — so a 10 → 5 layer maps (5×10)(10×1) → (5×1). Why this part exists: writing those two numbers down turns a stack trace into a one-line fix before the code ever runs.

Part 4 — Batching stacks examples as rows

A batch of 32 examples is a 32 × n matrix, one example per row, where n is the number of inputs. The layer is applied as A = XWᵀ + b, which for 10 → 5 reads (32×10)(10×5) → (32×5); the transpose exists only so the inner dimensions meet. Each row is computed independently of every other row. Why this part exists: row-per-example is what lets one matrix multiply serve 32 examples, and a wrong transpose is the classic silent bug.

Part 5 — The bias broadcasts down the batch

b has length n_out, but XWᵀ has 32 rows. The addition repeats the same vector on every row, so row 7 receives b exactly as row 1 does. This is broadcasting, and it is the one place where mismatched shapes are intended. Why this part exists: without a shared bias every example would need its own offset, and the batch would stop being 32 copies of one model.

Part 6 — Depth composes, width widens

Depth is the number of weight matrices; width is the number of units inside a layer. Width lets one layer ask more questions in parallel; depth lets later layers read combinations of earlier answers, so an edge detector feeds a shape detector feeds an object detector. Two layers of 64 units cost 4,160 parameters each, and the second can only build combinations of the first layer's 64 signals. Why this part exists: the two are separate budgets, and knowing which one you are buying stops you from adding layers when you only needed a wider one.

Part 7 — Parameter counts come from shapes alone

Each layer owns n_in·n_out weights plus n_out biases. A 784 → 128 → 10 network costs 784·128 + 128 = 100,480 in the first layer and 128·10 + 10 = 1,290 in the second. Why this part exists: the total predicts memory and overfitting risk before training, and a mismatch with the printed count locates a wiring error in seconds.

1. One example, two layers

x = [1, −1], W¹ = [[1, 2], [−1, 0]], b¹ = [0, 1], ReLU, then W² = [1, 1] and b² = −0.5 with a sigmoid on the output. Take it in five rows.

What to notice. The ReLU destroyed everything: both hidden units sat at or below zero, so a¹ = [0, 0] and the output depended only on b². The number 0.378 is what a network says when it has forgotten the input. Change x to anything at all and the answer stays 0.378 until at least one hidden unit crosses zero.

2. The same weights on a batch of three

The difference lives in the second unit, where [0, 1] keeps a 1 and [2, 0] loses its negative. That is the batch doing its job: three examples, one set of weights, three separate verdicts.

The trap

Most common wrong mental model

"If the shapes work out, the layer is correct." It feels right because nothing errors: a square matrix makes Wx and xW identical in shape, and broadcasting silently stretches a length-5 bias across 32 rows — which is exactly what you wanted that one time.

Correction: only the bias is allowed to broadcast. For everything else, compare the pair of numbers before multiplying: (32×10) against (5×10) does not work in that order and needs Wᵀ. A run that produces a shape has not proved it produced the right one.

The tell: loss falls, validation accuracy sits at chance, and two very different inputs return nearly the same prediction — the network is averaging across examples instead of separating them. Print W.shape, X.shape and the output shape once per layer; if the input's last number is not W's last number when you write XWᵀ, stop.

Retrieval check

  1. Layer 1: 10 units. Layer 2: 5 units. What are the shapes of W², b², and the output for a batch of 32?
    Answer

    W² is 5 × 10, b² is 5, output is 32 × 5. The batch dimension only appears at the edges, never in the weights.

  2. In the worked example, why did the network output exactly 0.378 regardless of the input's second feature?
    Answer

    Both ReLU units were clipped to 0, so z² = b² = −0.5 for every input. The hidden layer stopped transmitting information; only the bias survived.

  3. Where does the parameter count for a layer come from?
    Answer

    nˡ × nˡ⁻¹ weights plus nˡ biases. A 512 → 512 layer has 262,144 + 512 = 262,656 parameters.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
x = np.array([1., -1.])
W1, b1 = np.array([[1., 2.], [-1., 0.]]), np.array([0., 1.])
z1 = W1 @ x + b1
a1 = np.maximum(0, z1)
W2, b2 = np.array([1., 1.]), -.5
z2 = W2 @ a1 + b2
