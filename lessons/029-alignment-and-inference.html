Alignment & inference

You can explain SFT → RLHF/DPO, and how context window and temperature shape output.

Why this matters

Pretraining teaches the model to continue text — including text that argues, lies, or refuses. Alignment is the stage that makes it useful, and it is where most "the model is weird" behaviour originates.

The one core idea

Alignment optimises a proxy for human preference on top of a fixed base model. Every method differs only in how that preference signal is collected and optimised.

How it actually works

StageDataObjective
SFTDemonstrations: prompt → ideal answerCross-entropy on the answer tokens
Reward modelPairs: A is better than BBradley–Terry: −log σ(r(A) − r(B))
RLHFPrompts sampled freshPPO maximising r(x,y) − β·KL(π‖π_SFT)
DPOThe same preference pairsClosed-form loss; no reward model, no RL loop
  • KL penalty keeps the policy near the SFT model, preventing it from drifting into reward-model exploits.
  • DPO skips the RL machinery: it reparameterises the reward so the optimum of the preference objective can be written as a classification loss on the policy's own log-probabilities.
  • Context window: fixed maximum tokens; everything beyond is truncated, and attention cost grows quadratically.
  • Sampling: logits → divide by temperature T → softmax → sample. T → 0 is greedy; T = 1 is the model's native distribution.
  • KV cache: stored keys/values for past tokens make generation linear per new token instead of quadratic over the whole prefix.

Worked example

1. Temperature, numerically

Logits [2, 1, 0]:

TemperatureAdjusted logitsProbabilities
1.0[2, 1, 0][0.665, 0.245, 0.090]
0.5[4, 2, 0][0.867, 0.117, 0.016]

Low temperature sharpens; it does not add knowledge. At T = 0.5 the top token is 87% likely — fluency rises and diversity collapses. Turning temperature up does not make the model "more creative"; it makes rare tokens more likely, including wrong ones.

2. Two ways to hack the reward

The reward model was trained on comparisons, not on truth. A policy that produces confident, long, agreeable answers scores well even when wrong. That is reward hacking, and it is why the KL penalty and periodic human evaluation exist.

The trap

Most common wrong mental model

"RLHF makes the model more truthful." It makes the model better at satisfying the reward model. If the reward model prefers confidence, you get confidence — including confident errors. Truthfulness requires verification, not preference optimisation.

Second trap: expecting T = 0 to be deterministic. Batching, floating-point non-associativity and hardware scheduling all change results slightly; greedy decoding is reproducible on one machine, not across machines.

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. What does the KL term in RLHF actually prevent?
    Answer

    Large drift from the SFT policy. Without it, PPO finds inputs where the reward model is wrong and exploits them, producing degenerate but high-scoring text.

  2. Why does DPO need preference pairs but no reward model?
    Answer

    It derives a loss directly on the policy's log-probabilities that has the same optimum as the preference objective, so the intermediate reward network is not needed.

  3. A model at T = 0.2 repeats itself. What is happening?
    Answer

    Sharpening pushes probability mass onto the single most likely token, so the same phrase recurs. Raising temperature or adding a repetition penalty restores diversity.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
def softmax(z):
    e = np.exp(z - z.max()); return e / e.sum()
logits = np.array([2., 1., 0.])
for T in (0.5, 1.0, 2.0):
    print(f"T={T}: {softmax(logits / T).round(3)}")
# DPO-style preference loss on two completions
