Convolutions & CNNs

You can compute a convolution by hand, size its output, and count its parameters without counting pixels.

Neural NetworksDeep Learning

Why this matters— convolutions

An image is not a spreadsheet with shuffled columns. A pixel means something because of the pixels beside it, and the same edge or patch of fur can appear anywhere in the frame. A dense layer knows neither fact: it gives every position its own weights and ignores the grid. A convolution bakes both facts in, which is why it needs a thousandth of the parameters.

The failure it prevents. Connect a 224×224 colour image to 64 hidden units with a dense layer and you need 224 × 224 × 3 × 64 = 9,633,792 weights before the bias. The model memorises positions rather than patterns, and a cat moved 40 pixels to the left becomes a different input. An exam question asks for the parameter count of a convolutional layer; "9.6 million" is the answer that reveals the wrong architecture.

The one core idea— convolutions

A convolution takes a small filter — a 3×3 grid of weights is typical — and slides it across the image. At each position it multiplies the filter by the patch underneath, adds the nine products, and writes one number into a feature map. The same nine weights are used at every position, so the layer learns one detector for "vertical edge" rather than a separate detector for every location.

In one line: a convolution is a dot product applied to a patch, repeated everywhere with shared weights. Stack the maps and the next filter combines their outputs, so a 3×3 filter at layer two sees a 5×5 region of the original image; by layer four the model is looking at whole objects.

local patch + shared weights

Locality says nearby pixels interact; sharing says a pattern matters wherever it appears.

How it actually works— convolutions

Part 1 — The patch and the dot product

An image is a tensor of shape H × W × C: height, width, channels. A filter has shape k × k × C — the same depth as its input — and a bias. At one position, the response is the sum of elementwise products over the patch plus the bias, then passed through a nonlinearity such as ReLU, which replaces negatives with zero. This is exactly the neuron from Book 3, except its inputs are a patch of pixels rather than a whole row.

Why the depth matches: a colour edge is a pattern across red, green and blue together. The filter carries one weight per channel per position, so it can respond to "red high, blue low" as one pattern.

Part 2 — Output size, stride and padding

With input size H, kernel k, padding p pixels on each side, and stride s pixels between positions, the output side is

H_out = ⌊(H + 2p − k) / s⌋ + 1

Padding adds a border of zeros so the filter can centre on edge pixels; without it, each convolution shrinks the image by k − 1. Stride skips positions, shrinking the output and enlarging the region each later neuron sees.

Part 3 — Channels and parameter count

One filter produces one output channel. To produce C_out channels you use C_out filters, and the layer's parameter count is

C_out × (C_in × k × k + 1)

The +1 is the bias per filter. Notice what is absent: the image size. A 3×3 filter from 3 channels to 64 needs 64 × (3 × 9 + 1) = 1,792 parameters at 224×224 and at 32×32 alike; the dense layer's count grows with every pixel.

Part 4 — Depth, receptive field and pooling

Each 3×3 convolution adds two pixels to the reach of a neuron. Three stacked 3×3 convolutions give a 7×7 receptive field: 3 → 5 → 7. That is why CNNs build simple detectors first — edges, colour blobs — and combine them into textures, parts, then objects.

Pooling takes the maximum (or mean) over a small window, usually 2×2 with stride 2, halving the map. It buys some tolerance to small shifts and cuts compute. It does not make the network invariant to large moves, and global average pooling discards location entirely — useful for "is there a cat?", useless for "where is the cat?".

Worked example— convolutions

1. A vertical-edge filter on a 5×5 image

Every row of the image is 0, 0, 1, 1, 1. The filter is a vertical edge detector with rows −1, 0, 1. With no padding and stride 1, the output is 3×3.

Output cellPatch columnsArithmeticValue
top-left0–23 × (−1×0 + 0×0 + 1×1)3
top-middle1–33 × (−1×0 + 0×1 + 1×1)3
top-right2–43 × (−1×1 + 0×1 + 1×1)0

Read it as a sentence. The filter sums the right column and subtracts the left. A window that sees mostly zeros on the left and ones on the right scores 3; a window sitting entirely inside the ones scores −1 + 1 = 0. The full map is three identical rows of 3, 3, 0.

Change the stride to 2. The output side becomes ⌊(5 − 3)/2⌋ + 1 = 2, sampling patches at columns 0 and 2, rows 0 and 2: [[3, 0], [3, 0]]. Stride 2 kept every other response and halved the map.

2. Counting parameters

A layer takes 3 input channels and produces 8 output channels with a 3×3 kernel.

StepArithmeticCount
Weights per filter3 × 3 × 327
With bias27 + 128
Eight filters8 × 28224

Read it as a sentence. 224 numbers define the whole layer, whether it runs on a 32×32 thumbnail or a 4K frame. The dense alternative at 224×224 needs 9,633,792 weights for only 64 outputs — about 5,376 times more.

What to notice. The convolutional layer is cheaper because it makes two assumptions: that nearby pixels interact (locality) and that a pattern is worth detecting everywhere (weight sharing). When those assumptions are false — shuffled tabular columns — the saving disappears and the architecture is the wrong tool.

The trap— convolutions

Most common wrong mental model

"A CNN learns a separate detector for each location, and pooling makes it see the whole image." The filter is one set of weights reused at every position; that is the entire saving. And a neuron early in the network sees only its local patch — the receptive field grows with depth, not with pooling alone.

It feels right because the feature map is the same size as the image, so it looks as though each output cell had its own private weights. It also feels right because a cat is still recognised after moving, which sounds like invariance; in truth the response moves with the cat (equivariance), and only pooling or global pooling turns that into partial invariance.

Correction: say "shared filter, local patch, growing receptive field". Translation equivariance is built in; invariance to rotation, scale or large shifts is not, and needs augmentation, pooling, or more depth.

The tell: the parameter count does not change when you double the image size, a shift of the input shifts the feature map rather than scrambling it, and the same filter responds to the same pattern in the corner and the centre. If a model instead degrades sharply when an object moves ten pixels, suspect a dense layer where a convolution belongs.

Retrieval check— convolutions

  1. A 32×32 image goes through a 5×5 filter with padding 2 and stride 1. What is the output size?
    Answer

    (32 + 4 − 5)/1 + 1 = 32. Padding 2 on each side exactly compensates for a 5×5 kernel, so the map keeps the input size.

  2. How many parameters in a 3×3 layer with 3 input channels and 16 output channels, bias included?
    Answer

    16 × (3 × 3 × 3 + 1) = 16 × 28 = 448. Each of the 16 filters has 27 weights plus one bias.

  3. Does a convolution give translation invariance? Be precise.
    Answer

    It gives translation equivariance: shift the input and the feature map shifts by the same amount. Invariance — the same output regardless of position — requires pooling, global pooling, or training that encourages it, and is only approximate.

Solve it · 045 — 2-D convolution with stride and padding

Build it in Colab— convolutions

Runnable, NumPy-only: open the notebook in Colab · local copy. It convolves a small image with an edge filter, plots the feature map, and checks the output-size formula.

import numpy as np
img = np.zeros((5, 5))                  # a blank grey image
img[:, 2:] = 1.0                        # a bright right-hand side
k = np.array([[-1., 0., 1.], [-1., 0., 1.], [-1., 0., 1.]])  # vertical edge
out = np.zeros((3, 3))                  # valid convolution, stride 1
for i in range(3):                      # three output rows
    for j in range(3):                  # three output columns
        out[i, j] = (img[i:i+3, j:j+3] * k).sum()  # patch dot filter
print(out)
