Two solution families: value vs policy

You can contrast Q-learning and policy gradient on what they learn and when each fails.

Why this matters

Every RL algorithm you will read about is one of two things, or a hybrid. Knowing which is which tells you immediately whether it can reuse old data and whether it can handle continuous actions.

The one core idea

Value-based methods learn Q(s,a) and act greedily. Policy-based methods learn π(a|s) directly by gradient ascent on expected return. Actor–critic learns both.

How it actually works

Value-based (Q-learning)Policy gradient (REINFORCE)
LearnsQ(s,a)π_θ(a|s)
PolicyImplicit: argmaxExplicit, stochastic
DataOff-policy — replay any transitionOn-policy — must use current policy
Continuous actionsNeeds an optimiser inside argmaxNatural fit
Failure modeInstability with function approximationHigh variance
Q-learning: Q(s,a) ← Q(s,a) + α[ r + γ max_{a′} Q(s′,a′) − Q(s,a) ] REINFORCE: θ ← θ + α ∇_θ log π_θ(a|s) · G_t
  • max inside Q-learning makes it off-policy: it learns about the best action regardless of what the agent did. That is why replay buffers work (topic 24).
  • REINFORCE weights the log-probability gradient by the realised return. Actions followed by good returns become more likely. Unbiased, but the return is a single noisy sample.
  • Actor–critic replaces G_t with Q(s,a) − V(s), the advantage: how much better this action was than average. Lower variance, some bias.

Worked example

1. One Q-learning update

Q = 0.5, reward 1, γ = 0.9, next-state max Q′ = 0.8, α = 0.1:

QuantityValue
Target1 + 0.9(0.8) = 1.72
TD error1.72 − 0.5 = 1.22
New Q0.5 + 0.1(1.22) = 0.622

2. One policy-gradient update

Policy says P(left) = 0.7, P(right) = 0.3. You took left and got return 5. The gradient pushes log π(left) up, increasing P(left). If the return had been −5, it would push it down. The magnitude scales with how surprising the action was — a 0.7-probability action gets a smaller push than a 0.05 one.

The trap

Most common wrong mental model

"Q-learning is strictly better because it reuses data." Off-policy reuse is exactly what destabilises value-based methods once you add a neural network: the deadly triad (topic 23). PPO dominates real-world continuous control for the opposite reason.

Second trap: assuming a policy gradient needs a differentiable reward. It does not — the gradient flows through log π, so the reward can be a black box (a win/loss, a human rating).

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. You have a robot arm with 7 continuous joints. Which family, and why?
    Answer

    Policy gradient (or actor–critic). argmax_a Q(s,a) over a continuous 7-D action space requires solving an optimisation at every step; a policy outputs the action directly.

  2. Why can Q-learning learn from transitions generated by an old, bad policy?
    Answer

    Its target uses max_{a′} Q(s′,a′), which is independent of the behaviour policy. The update asks "what would the best action give", not "what did I do".

  3. What does the advantage Q − V add over raw return G?
    Answer

    It subtracts the baseline: "better than average here" instead of "good in absolute terms". Same expected gradient, much lower variance.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
Q, r, gamma, alpha = 0.5, 1.0, 0.9, 0.1
target = r + gamma * 0.8
print("Q-learning: target", target, "TD error", round(target - Q, 2),
      "new Q", round(Q + alpha * (target - Q), 3))
# policy gradient on a two-action bandit
probs = np.array([0.7, 0.3])
