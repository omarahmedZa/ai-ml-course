Unit 5 · Reinforcement learning · Topic 19 of 35

The RL frame: states, actions, rewards

You can formalize a task as (S, A, P, R, γ) and compute a return.

Why this matters

RL is the only unit where the data is generated by your own decisions. Get the formal frame right and the rest of the unit is algebra; get the reward wrong and the agent will optimise something you did not intend.

The one core idea

An agent sees a state, takes an action, receives a reward, and lands in a new state. The objective is not the next reward — it is the discounted sum of all future rewards.

How it actually works

SymbolNameMeaning
SStatesEverything the agent can observe
AActionsChoices available at each state
PTransitionP(s′ | s, a) — dynamics, often stochastic
RRewardR(s, a, s′) — scalar feedback
γDiscount0 ≤ γ < 1 — how much the future counts
G_t = r_{t+1} + γr_{t+2} + γ²r_{t+3} + … π: S → distribution over A
  • Policy π — the thing being learned. Deterministic (a = π(s)) or stochastic (π(a|s)).
  • Return G_t — the quantity being maximised. Not the reward.
  • Episodic tasks terminate (a game); continuing tasks do not (a server). Discounting is what makes continuing returns finite.
  • γ = 0 makes the agent myopic — it only cares about the next reward. γ → 1 makes it plan far ahead, at the cost of higher variance.

Worked example

1. Return with a discount

Reward 1 every step for 10 steps, γ = 0.9:

QuantityFormulaValue
Undiscounted10 × 110.0
Discounted(1 − 0.9¹⁰)/0.16.51
Effective horizon1/(1 − γ)10 steps

1/(1−γ) is the intuition worth memorising: γ = 0.99 means "roughly the next 100 steps matter".

2. Writing a task down

Grid world: S = 25 cells, A = {up, down, left, right}, P = deterministic except a 10% slip, R = −1 per step, +10 at the goal, γ = 0.95. Now every algorithm in this unit applies without further thought. If you cannot fill these five fields, the problem is not yet an RL problem.

The trap

Most common wrong mental model

"The agent maximises reward." It maximises return, and the discount changes which policy is optimal. A reward of 11 arriving in 100 steps is worth about 0.0003 at γ = 0.9 — far worse than 1 now.

Second trap: specifying a reward that is a proxy for the goal. An agent told to maximise "time alive" will learn to avoid finishing. Reward design is the specification.

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. Reward 2 at every step, 5 steps, γ = 0.5. Compute the return.
    Answer

    2(1 + 0.5 + 0.25 + 0.125 + 0.0625) = 3.875. Undiscounted it would be 10 — the discount more than halves it.

  2. What does γ = 0 do to the agent's behaviour?
    Answer

    It becomes entirely myopic: only r_{t+1} matters. Any action with a delayed payoff is invisible, which is usually a bug, not a design.

  3. Why is a continuing task problematic without a discount?
    Answer

    The return is an infinite sum of positive rewards — it diverges, so no policy can be "better". γ < 1 makes the sum finite and the comparison meaningful.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
def discounted(rewards, gamma):
    return sum((gamma ** k) * r for k, r in enumerate(rewards))
for gamma in (0.0, 0.9, 0.99):
    print(f"gamma={gamma}: return over 10 unit rewards = {discounted([1]*10, gamma):.3f}")
    print(f"           a reward of 11 at step 100 is worth {11 * gamma**100:.6f}")
print("effective horizon 1/(1-gamma):", [round(1/(1-g), 1) for g in (0.9, 0.99, 0.999)])
