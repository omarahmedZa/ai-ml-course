Evaluating language models

You can compute perplexity and a benchmark's error bar, and say what each one does not measure.

Language & TransformersNLP & Transformers

Why this matters— the metric

A language model gives a probability for every token, not one answer, so "is this model better?" cannot be read from one output. You need a number over many examples, and you need to know what it ignores. Two scores dominate: perplexity, how surprised the model is by real text, and benchmark accuracy, how often its answer is right.

The failure it prevents. A team swaps models for a four-point benchmark gain and finds the new one worse at extracting invoice dates. The gain was inside the noise and the benchmark held no invoices. "98% accuracy" on 50 examples, with no error bar, is the same gap in an exam answer; the error is about 2 points.

The one core idea— the proxy

Every language-model score is a proxy: a cheap number standing in for "useful to a person". Perplexity stands in for fluency — a model that puts high probability on real text has learned the statistics of language. Accuracy stands in for skill — a model that answers held-out questions has learned something transferable. Neither is the thing you want, and both can be gamed.

In one line: fix the data, compute the average surprise or the hit rate, then attach an error bar before comparing. Perplexity is exp of average negative log-probability; accuracy is hits over attempts. The first is smooth, the second noisy.

PPL = exp( −(1/N) Σᵢ log p(tokenᵢ | context) )

Average surprise, pushed back through the exponential so a perfect model scores 1 and a coin flip over 10 tokens scores 10.

How it actually works— the pipeline

Five parts, in the order a careful evaluation runs them.

Part 1 — Freeze the text and the tokenizer

Pick held-out text the model never saw, tokenize it with the model's own tokenizer, and record the token count N. Perplexity is per token, so a different vocabulary changes the denominator and scores stop being comparable.

Part 2 — Score each token in context

At each position the model gives a probability to the token that actually appears, given everything before it. Take the log: a certain token contributes 0, one given 1% contributes −4.6. Logs turn a product into an averageable sum.

Part 3 — Average, then exponentiate

Average the negative logs over N tokens, then apply exp. The result is perplexity: roughly how many equally likely options the model felt it was choosing between. It restores an intuitive scale that raw log-loss lacks.

Part 4 — Measure a task, and its error bar

Score correctness per question, then divide. Each is a coin flip with unknown bias p, so the score wobbles: standard error is √(p(1−p)/n)(square root) and a 95% interval is two standard errors either side. Without it, a 2-point win on 200 questions looks like progress.

Part 5 — Hold the harness fixed

Prompt template, few-shot count, parsing, temperature and seed all move the score. Fix and publish them, then rerun the baseline under the same harness. Many reported gains are prompt changes.

Worked example— the arithmetic

1. Perplexity of a four-token continuation

The model sees "the cat sat" and scores the continuation "on the mat", assigning p = [0.50, 0.25, 0.50, 1.00] to the four tokens in turn.

Step 1 — add the surprises: 0.693 + 1.386 + 0.693 + 0 = 2.772. Step 2 — divide by four: 2.772 / 4 = 0.693. Step 3 — exponentiate: e^0.693 = 2.0. In words: "on average the model felt it was choosing between two equally likely tokens."

Why the exponential. Without it the score is 0.693 nats, a unit with no intuition. With it, a certain model scores 1.0 and one spreading probability over 10 candidates scores 10.

2. Accuracy on 200 questions

140 correct out of 200 gives 0.70. The standard error is √(0.70 × 0.30 / 200) = √0.00105 = 0.032, or 3.2 points. Two standard errors is 6.4 points, so the 95% interval runs from 63.6% to 76.4%.

Four times the questions halves the error bar. Perplexity and accuracy can also disagree: a model can predict text better and still follow the answer format worse.

The trap— the leak

Most common wrong mental model

"The benchmark score measures the model's ability." It measures the score on that benchmark, under that prompt, against that answer key — and benchmarks leak.

It feels right because 84.2% looks like a measurement. But test questions get scraped into pretraining data, so the model may have seen the answers; shuffling options moves the score because the model prefers option A; and a judge model brings its own biases. None of this shows in the number.

Correction: ask three questions of any score — was the test set held out, was the harness identical for both models, and is the gap larger than the error bar? A fourth catches the rest: does the benchmark resemble the job?

The tell: the score collapses when you reorder options, or rises only when you add "think step by step" for the new model. Contamination looks different: near-perfect scores on rare, verbatim-specific questions while paraphrases stay ordinary. A 0.4-point gain on 500 questions is smaller than its 2.2-point error bar.

Retrieval check— recall

  1. A model assigns probability 0.5 to each of four tokens. What is its perplexity on that text?
    Answer

    Each token contributes 0.693, the average is 0.693, and e^0.693 = 2.0 — two equally likely choices per token.

  2. Model A scores 72% and model B 75% on 100 questions. Is B better?
    Answer

    Not established. The standard error near 0.73 is about 4.4 points, so a 3-point gap sits inside the noise. More questions, or a paired comparison, is needed.

  3. Perplexity improved but task score did not. Name one explanation.
    Answer

    The new model predicts ordinary text better but has not learned the answer format, or the task needs a fact the text lacks. Fluency and skill are different targets.

Solve it · 051 — Perplexity, checked

Build it in Colab— the notebook

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. It computes perplexity by hand and plots the error bar against sample size.

import numpy as np
p = np.array([0.50, 0.25, 0.50, 1.00])   # probability of each observed token
nll = -np.log(p).mean()                   # 0.693
print(f"perplexity = {np.exp(nll):.2f}")
n, hits = 200, 140
se = np.sqrt((hits/n) * (1 - hits/n) / n)  # 0.032
print(f"accuracy = {hits/n:.3f} +/- {se:.3f}")

Extra practice— drill

Two harder questions. Three attempts each — the answer unlocks only after the third miss. Correct on the first try is worth 2 points, later 1, revealed 0.
