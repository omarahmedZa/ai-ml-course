Evaluating explanations

You can test faithfulness and explain the correlation ≠ causation trap.

Why this matters

An explanation that looks convincing and is wrong is worse than no explanation: it launders a black box into false confidence. This topic is the quality control that Unit 8 otherwise lacks.

The one core idea

Explanations must be judged on faithfulness (does it reflect the model's actual computation?) not plausibility (does a human like it?). The two frequently disagree.

How it actually works

  • Deletion test: remove the top-k attributed features and measure the drop in output. A faithful explanation removes features that actually mattered.
  • Insertion test: add features from least to most important; a faithful ranking recovers the prediction quickly.
  • Model randomisation sanity check: retrain with shuffled labels or randomise weights layer by layer. A faithful method's output must change. Many saliency maps do not — they are edge detectors, not explanations (Adebayo et al., 2018).
  • Stability: perturb the input slightly or re-sample the explainer; a stable method returns similar attributions.
  • Explanation hacking: a model trained with an explanation penalty can learn to produce nice explanations while behaving differently. Never optimise the explainer and the model together without an independent check.

Worked example

1. Deletion test, two methods

Image classifier, 5,000 test images, AUC 0.94.

Method A's "important" pixels really are load-bearing; removing them destroys the prediction. Method B's are decorative — its map is smooth and pretty, and nearly useless. Plausibility would have ranked B first.

2. The randomisation test in one line

Replace the trained weights with random ones, keeping the architecture. A saliency map that barely changes was never about the learned features. Run this before publishing any heatmap.

The trap

Most common wrong mental model

"A domain expert found the explanation convincing, so it is validated." Human judgement measures plausibility, and humans are systematically fooled by smooth, local, sparse-looking maps. Faithfulness needs a perturbation experiment, not an opinion.

Second trap: confusing "the model attends here" with "this caused the decision". Attention and attribution are correlational summaries of one forward pass (topic 26).

Retrieval check

  1. What is the difference between faithfulness and plausibility?
    Answer

    Faithfulness: the explanation reflects the model's actual computation, testable by perturbation. Plausibility: it matches human intuition. A method can score high on one and low on the other.

  2. Why does the model-randomisation test catch fake saliency?
    Answer

    If the weights are randomised, the learned features are gone. An explanation that ignores this is responding to input statistics (edges, contrast), not to the model.

  3. You remove the top 5 features and accuracy does not change. What do you conclude?
    Answer

    The attribution is not faithful for this model — those features were not necessary for the prediction. Either the method is wrong, or the model is using redundant features.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
rng = np.random.default_rng(0)
n_features = 20
true_importance = np.zeros(n_features)
true_importance[:3] = [3., 2., 1.]
X = rng.normal(size=(500, n_features))
y = (X @ true_importance > 0).astype(int)
