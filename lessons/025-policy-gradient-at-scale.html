Policy gradient at scale: REINFORCE → PPO

You can trace REINFORCE → baseline → actor–critic → PPO and explain the variance problem.

Why this matters

PPO is the default algorithm behind robot control, game agents, and the RLHF step that made chat models usable. If you understand three upgrades to REINFORCE, you understand all of it.

The one core idea

REINFORCE is correct but enormously noisy: one rollout estimates the gradient. Each upgrade — baseline, critic, clipping — reduces variance or prevents destructive updates without changing the objective.

How it actually works

∇J(θ) = E[ ∇_θ log π_θ(a|s) · A(s,a) ]
StageChangeFixes
REINFORCEWeight by return G_tNothing — high variance
+ baselineWeight by G_t − b(s)Variance; b can be any function of state
Actor–critic (A2C)b = V_φ(s), learnedVariance further; adds bias
+ GAEBlend 1-step and n-step advantages with λBias–variance tuning
PPOClip the probability ratio to [1−ε, 1+ε]Prevents a big, destructive update
  • Why a baseline is free: subtracting a state-dependent constant does not change the expected gradient, because Σ_a π(a|s)∇log π(a|s) = 0. It only removes variance.
  • Advantage A = Q − V: "how much better than average was this action here".
  • PPO objective: min(r_t A, clip(r_t, 1−ε, 1+ε) A), where r_t = π_new/π_old. ε is typically 0.2.
  • On-policy: after the update, the data is stale. PPO squeezes a few epochs out of it, then throws it away.

Worked example

1. The clip, concretely

ε = 0.2, advantage positive (the action was good), ratio r = 1.3:

TermValue
Unclipped1.3 × A
Clipped1.2 × A
Objective (min)1.2 × A

The gradient stops rewarding further increases beyond 1.2. If the advantage is negative, the clip works on the other side: r = 0.5 → clipped to 0.8, preventing an oversized decrease.

2. Why variance is the enemy

Returns in a task range from 0 to 100. Weighting one action's gradient by 100 instead of 40 is not a model error — it is sampling noise, and it moves the policy as if it were signal. A baseline turns "100 versus 40" into "60 versus 0", preserving the ranking while shrinking the magnitude.

The trap

Most common wrong mental model

"PPO's clip guarantees the policy changes by at most ε." It clips the objective, not the parameter update. Multiple epochs, momentum and shared parameters can still move the policy far. Clipping is a soft penalty, not a trust region.

Second trap: blaming the algorithm when PPO does not learn. Nine times out of ten it is reward scaling, advantage normalisation, or a learning rate that is too high for the batch size.

Retrieval check

  1. Why does subtracting a baseline not bias the policy gradient?
    Answer

    Because Σ_a π(a|s) ∇log π(a|s) = ∇Σ_a π(a|s) = ∇1 = 0. Any state-dependent baseline contributes zero in expectation, so only the variance changes.

  2. What is the probability ratio in PPO, and what is it measuring?
    Answer

    π_new(a|s) / π_old(a|s) — how much more (or less) likely the action has become since the data was collected. It is 1 when nothing has changed.

  3. Why is PPO described as sample-inefficient?
    Answer

    It is on-policy: once the policy updates, old rollouts are invalid and must be discarded. DQN can reuse a transition a million times; PPO uses it for a handful of epochs.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
ratio, adv, eps = 1.3, 2.0, 0.2
unclipped = ratio * adv
clipped = np.clip(ratio, 1 - eps, 1 + eps) * adv
print(f"ratio={ratio} adv={adv} -> unclipped={unclipped} clipped={clipped} objective={min(unclipped, clipped)}")
for r in (0.5, 1.0, 1.3):
    print(f"r={r}: objective={min(r * adv, np.clip(r, 1-eps, 1+eps) * adv):.2f}")
