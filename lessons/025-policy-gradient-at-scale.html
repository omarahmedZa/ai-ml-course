Policy gradient at scale: REINFORCE → PPO

You can trace REINFORCE → baseline → actor–critic → PPO and explain the variance problem.

Why this matters— policy gradient

PPO is the default algorithm behind robot control, game agents, and the RLHF step that made chat models usable. If you understand three upgrades to REINFORCE, you understand all of it.

You need this the moment actions are continuous — a torque, a joint angle, a throttle — because "take the max over a discrete table" has nothing to maximise. Policy gradient instead moves the probabilities themselves, which is why it also powers the fine-tuning of language models, where the "action" is a token. Two failures it prevents. The exam failure: "Subtract a baseline from the return. Prove the gradient is still unbiased, then say what did change." The proof is one line of algebra; the answer is variance, and "bias" loses the mark. The project failure: you run REINFORCE on returns spanning 0 to 100, one lucky episode returns 100 instead of 40, and the next update moves the policy so far that it never recovers. The gradient was correct and the step size was not.

The one core idea— policy gradient

Estimating a gradient from one rollout is an opinion poll of size one. The poll is unbiased — run it a million times and the average is right — but any single result can be wildly off, and you act on that single result. Every upgrade in this lesson leaves the average untouched and shrinks the spread around it.

In one line: same expected gradient, smaller variance. A state where all actions return 100 contributes a weight of 100 and no information; subtract V(s) = 100 and it contributes 0, while a state returning 0 or 40 contributes −50 or −10.

E[∇log π · (G − b(s))] = E[∇log π · G]

A state-only baseline leaves the expected gradient unchanged and shrinks only the variance around it.

How it actually works— policy gradient

Seven parts follow, each one an upgrade stacked on the last.

Part 1 — Parameterise the policy itself

The network outputs a probability per action, π_θ(a|s); for continuous control, the mean and spread of a Gaussian you then sample from. There is no value table to consult — the network's output is the behaviour. Why this part exists: a gradient needs something to differentiate, and behaviour is only differentiable once it is written as a function of θ.

Part 2 — The score function says "more likely"

∇_θ log π_θ(a|s) is the direction in weight space that raises the probability of the action just taken, measured at the current weights. It has the same shape as θ, so it can be added to θ directly. Why this part exists: it converts "that action was good" into a concrete nudge, and it never needs a derivative of the environment.

Part 3 — Weight the nudge by the return

The estimator is E[∇log π · G_t]: push up actions that returned a lot, push down actions that returned little. This is REINFORCE in full, and it is unbiased. Why this part exists: unweighted, every action would be pushed up equally, which changes nothing except the sharpness of the distribution.

Part 4 — A baseline removes the state's own value

Subtract b(s), any function of state alone: E[∇log π (G − b(s))]. Because Σ_a π(a|s)∇log π(a|s) = 0, the expectation does not move; only the spread around it shrinks. Why this part exists: the 100-everywhere state above contributes 100 of weight and zero learning signal.

Part 5 — A critic learns the baseline

Set b = V_φ(s), a second network trained by regression on observed returns. Then G − V is the advantage: how much better than this state's average the action was. Why this part exists: a hand-set baseline cannot follow a policy that improves, and the critic can — paying for it with bias whenever V_φ is wrong.

Part 6 — GAE blends one step with many

A one-step advantage has low variance and high bias; a full-episode return has the reverse. GAE mixes them: A = δ_t + γλδ_{t+1} + (γλ)²δ_{t+2} + …, where δ is a one-step TD error. Why this part exists: λ = 0 hands you the critic's guess and λ = 1 the raw return, so one dial replaces an argument about which is right.

Part 7 — Clip the ratio

PPO maximises min(rA, clip(r, 1−ε, 1+ε)A) with r = π_new/π_old and ε = 0.2. Inside the band this is the ordinary policy gradient; outside, the objective goes flat and further movement buys nothing. Why this part exists: on-policy data is used once, so a single destructive step wastes the whole rollout that produced it.

1. What a baseline removes, in numbers

Two states, two actions each. In the easy state every action returns 100, so there is nothing to learn there. In the hard state the actions return 40 and 0. Use each state's own average as the baseline.

What to notice. Raw returns average 60 with a spread of 7,200 in squared deviation; centred returns average 0 with a spread of 800 — nine times smaller. The two easy samples now contribute exactly nothing, which is right: they carry no preference between a1 and a2. Nothing was lost, because the expected gradient is identical either way. The same two hard samples still say "a1 good, a2 bad" at the same ratio, 20 to −20.

2. The clip, on both signs of advantage

ε = 0.2, so the allowed band is 0.8 to 1.2. A good action has A = +2; a bad one has A = −2.

What to notice. With A = +2 the objective stops at 2.4: whether the ratio is 1.3 or 2.0, the gradient beyond the band is zero, so an already-good action earns nothing more. With A = −2 the pattern is asymmetric — at ratio 2.0 the objective keeps falling to −4.0, because making a bad action twice as likely should still be punished. Only the reward side is capped. That asymmetry is what min does.

3. What λ does to one advantage

Two TD errors, δ₀ = 1.0 and δ₁ = 2.0, with γ = 0.9. GAE keeps two terms: δ₀ + (γλ)δ₁.

What to notice. λ = 0 trusts the critic completely and λ = 1 trusts the observed rewards completely, and every setting between is a weighted compromise — 1.90 is 45% of the way from 1.00 to 2.80. λ is not a learning rate and does not shrink the update; it decides how much of the future each advantage is allowed to see. Common values sit near 0.95, where the critic's bias is small next to the variance of a long return.

The trap— policy gradient

Most common wrong mental model

"PPO's clip guarantees the policy moves by at most ε." It feels right because ε = 0.2 is right there in the formula, and a bound that appears in the objective looks like a bound on the result. But the clip acts on the objective, not on the parameters.

Three things escape it. Multiple epochs on the same batch compound small steps; Adam's momentum carries direction across batches; and in a network with shared layers, one clipped ratio for one action still drags every other output. A ratio that should stop at 1.2 can drift to 1.9 over ten epochs while each individual objective term looks clipped.

Correction: clipping is a soft penalty on incentive, not a trust region on distance. Measure the actual change — mean KL between old and new policies — instead of assuming the formula delivered it.

The tell: after an update, the mean ratio on the same batch has drifted well past 1.2, or the KL spikes while every individual loss term looks capped. The second tell is a run that improves for one epoch and then degrades across epochs within a single batch — clipping cannot be the explanation, so look at epochs, learning rate and advantage normalisation before blaming the algorithm.

Retrieval check— policy gradient

  1. Why does subtracting a baseline not bias the policy gradient?
    Answer

    Because Σ_a π(a|s) ∇log π(a|s) = ∇Σ_a π(a|s) = ∇1 = 0. Any state-dependent baseline contributes zero in expectation, so only the variance changes.

  2. What is the probability ratio in PPO, and what is it measuring?
    Answer

    π_new(a|s) / π_old(a|s) — how much more (or less) likely the action has become since the data was collected. It is 1 when nothing has changed.

  3. Why is PPO described as sample-inefficient?
    Answer

    It is on-policy: once the policy updates, old rollouts are invalid and must be discarded. DQN can reuse a transition a million times; PPO uses it for a handful of epochs.

Build it in Colab— policy gradient

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. Sections, plots, sliders and line-by-line notes — run the cells in order, then change one number and rerun.

import numpy as np
ratio, adv, eps = 1.3, 2.0, 0.2
unclipped = ratio * adv
clipped = np.clip(ratio, 1 - eps, 1 + eps) * adv
print(f"ratio={ratio} adv={adv} -> unclipped={unclipped} clipped={clipped} objective={min(unclipped, clipped)}")
for r in (0.5, 1.0, 1.3):
    print(f"r={r}: objective={min(r * adv, np.clip(r, 1-eps, 1+eps) * adv):.2f}")
