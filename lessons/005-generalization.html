Generalization: overfitting, underfitting, and the gap

You can diagnose over- vs underfitting from train/test curves and pick the fix that matches the diagnosis.

Why this matters

This is the single most examined idea in Unit 1, and the first thing that will go wrong in your project. A model that scores 99% on data it has seen is a memory; a model that scores 85% on data it has not seen is a product.

The one core idea

Generalization is performance on unseen data. It is a property of the procedure (data + model class + training), not of the fitted model — and it is measured by holding data back.

How it actually works

  • Split: train (fit θ), validation (choose hyperparameters), test (report once, at the end). 60/20/20 is a sane default.
  • Underfitting: train loss high, val loss high → the model is too simple or undertrained. Fix: bigger model, better features, longer training.
  • Overfitting: train loss low, val loss high → the model learned noise. Fix: more data, regularization, simpler model, early stopping.
  • Bias–variance: expected error = bias² + variance + irreducible noise. Simple models are biased; complex ones are variance-heavy. The sweet spot is the model just complex enough for the signal.

Worked example

1. The same 20 points, two models

ModelTrain MSETest MSEVerdict
Degree 1 (line)0.900.95Underfit — both high
Degree 9 (wiggle)0.023.40Overfit — gap explodes

The degree-9 curve threads every training point by swinging wildly between them. Those swings are the model fitting noise, and they cost 3.4 MSE where it counts.

2. The fix, in order of cost

  1. More data — reduces variance, never fixes bias.
  2. Regularization — penalise large weights (weight decay, topic 12).
  3. Early stopping — halt when validation loss turns upward.
  4. Simpler model — the last resort, because it raises bias.

The trap

Most common wrong mental model

"I'll tune until the test score is good." Do that and the test set has become a validation set. Your reported number is then optimistic, and the gap reappears in production where you cannot measure it.

Leakage is the same disease in disguise: scaling or imputing before the split lets test statistics into training. Fit the scaler on train only, then apply it to test.

Retrieval check

  1. Train accuracy 0.99, validation 0.68. Name the diagnosis and two fixes that do not involve collecting more data.
    Answer

    Overfitting. Regularization (weight decay/dropout) and early stopping both reduce variance without new data. Reducing capacity also works, at the risk of bias.

  2. Why is a validation set necessary if you already have a test set?
    Answer

    Because every decision made using test performance contaminates it. Validation absorbs the tuning; test measures the final, frozen choice exactly once.

  3. Both train and validation loss are 0.60 and flat. Does more data help?
    Answer

    Barely. That is bias, not variance — the model cannot represent the pattern. More data lowers variance; it will not teach a line to curve.
