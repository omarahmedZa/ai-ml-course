MDPs & dynamic programming

You can write an MDP's five parts and run value iteration on a three-state chain by hand.

Reinforcement LearningRL

Why this matters— the model

A reinforcement-learning problem needs a precise description before any algorithm can run. The description is a Markov decision process: states, actions, transition probabilities, rewards and a discount. Write those five parts and a vague task becomes a table you can compute with.

The failure it prevents. An agent is rewarded for each item it ships and learns to ship everything immediately, emptying the warehouse. The reward was attached to the wrong event; no amount of training fixes that. "Find the optimal policy" answered with the action that pays most right now is a one-step answer to an infinite-horizon question.

The one core idea— the Bellman backup

An MDP is the tuple (S, A, P, R, γ)(gamma, P): S is the set of states, A the actions, P(s′ | s, a) the probability of landing in s′, R(s, a) the reward for a transition, and γ a number in [0, 1) that prices the future. A policy π(a | s)(pi) says what to do in each state. Its value is the expected discounted return, not the next reward.

In one line: the value of a state is its best one-step reward plus the discounted value of wherever you land. That sentence is the Bellman equation, and dynamic programming is what you get when you apply it to every state over and over until the numbers stop moving.

V(s) ← maxₐ [ R(s,a) + γ Σₛ′ P(s′|s,a) V(s′) ]

The backup: look one step ahead, borrow the current estimate for the next state, and keep the better action.

How it actually works— the sweep

Five parts to specify, then one loop to solve.

Part 1 — List the states, including the terminal one

Every distinguishable situation gets a state. Add an absorbing terminal state with value 0 so episodes can end. Why this part exists: a missing state merges two situations, and the agent behaves as if they were one.

Part 2 — List the actions and the transitions

For each state, list legal actions and, for each, the next states with probabilities summing to 1. Why this part exists: the transition table is the environment's physics; without it you can sample, not compute.

Part 3 — Put rewards on transitions

A reward belongs to (s, a, s′), not to a state alone. Write down which event pays and how much. Why this part exists: placement defines behaviour — reward "shipping" and the agent empties the shelf.

Part 4 — Choose the discount γ

γ = 0.9 prices a reward one step away at 0.9, two steps at 0.81, ten steps at 0.35; γ = 0 is myopic. Why this part exists: it is the exchange rate between now and later, and decides whether a slow good plan beats a fast mediocre one.

Part 5 — Sweep until the values settle

Initialise values at 0, apply the backup to every state, and repeat. Stop when the largest change is below a small threshold, then read the policy as the argmax action. Why this part exists: the Bellman equation is a fixed point, and repeated application converges to it when γ < 1.

Worked example— the arithmetic

1. The five parts, written down

States S = {A, B, C} with C terminal. Actions: at A, shortcut or scenic; at B, go. Transitions are deterministic, so each probability is 1 or 0. Rewards are 0 for shortcut, 0.5 for scenic, 1 for go. Discount γ = 0.9.

2. Values by hand

Work backwards. The terminal state is worth 0. B pays 1 and then ends: V(B) = 1 + 0.9(0) = 1.0. At A, compare the two actions.

Sweep 1. With all next values at 0, A compares 0 + 0.9(0) = 0 against 0.5 + 0.9(0) = 0.5, so scenic wins and V(A) = 0.5. B gets 1 + 0.9(0) = 1.0.

Sweep 2. Now B is worth 1.0, so A compares 0 + 0.9(1.0) = 0.9 against 0.5 + 0.9(0) = 0.5. Shortcut wins, V(A) = 0.9, and the largest change is 0.4.

Sweep 3. Nothing moves: 0.9 and 1.0 reproduce themselves. The loop stops, and the policy is shortcut at A, go at B.

The trap— the horizon

Most common wrong mental model

"V(s) is the reward of being in state s." Value is the expected discounted return from that state onward, under a policy, and it includes rewards not yet received.

It feels right because the number is attached to a state and often equals a reward in the simplest chain. But the same state can be worth different amounts under different policies, and its value changes when γ changes even though every reward is untouched. A state with no reward can be the most valuable one on the board.

Correction: read V(s) as "what I expect to collect from here", and Q(s,a) as "what I expect to collect if I take this action first". Neither is a property of the state alone.

The tell: a value exceeds the largest single reward — 0.9 is fine here, but 8.0 with a maximum reward of 1.0 means the future is being accumulated, not double-counted. The second tell is a policy that changes when you alter only γ. The third is a zero in a non-terminal state, meaning the backup never reached it.

Retrieval check— recall

  1. Name the five parts of an MDP.
    Answer

    States, actions, transition probabilities P(s′|s,a), rewards R(s,a), and discount γ.

  2. Why does value iteration start from zeros and still converge?
    Answer

    The Bellman operator is a contraction when γ < 1, so repeated backups shrink the error toward a unique fixed point from any start.

  3. With γ = 0.9, what is a reward of 1 worth two steps away?
    Answer

    0.9² = 0.81. Each step multiplies by another 0.9, so distance is priced exponentially.

Build it in Colab— the notebook

Runnable, NumPy-only: open the notebook in Colab · local copy. It runs value iteration on this chain and prints each sweep.

import numpy as np
V = np.zeros(3)                      # A, B, C(terminal)
gamma = 0.9
for sweep in range(10):
    V[0] = max(0 + gamma * V[1], 0.5 + gamma * V[2])   # A
    V[1] = 1 + gamma * V[2]                            # B
    print(sweep, V.round(2))         # 0.5 1.0 0.0, then 0.9 1.0 0.0
