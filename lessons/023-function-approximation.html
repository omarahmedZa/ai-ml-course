Function approximation: why tables die

You can explain why tabular RL fails at scale, and why approximation removes the convergence guarantee.

Why this matters

Every deep RL result — Atari, Go, robot locomotion, RLHF — exists because someone replaced a table with a neural network. The price is the guarantee, and the exam will ask what was lost.

You reach for it the moment a state stops being a small integer: pixels, joint angles, board positions, sentences. It blocks two specific losses. The exam loss: "Tabular Q-learning converges to Q*. You swap the table for a network — does convergence survive?" Two marks for no, four more for naming approximation, bootstrapping and off-policy data together. The project loss: you size a table for a 100×100 grid, see 40,000 entries, call that small, train overnight, and find the agent still walks into walls after filling a fraction of them. Approximation answers for states it never saw; that is the whole trade.

The one core idea

A table is a notebook with one printed page per situation — and most pages stay blank forever. A network is a formula fitted to the pages you did fill, so an empty page still receives an answer, guessed from similar pages you did fill. The mental model is interpolation: nearby inputs get nearby outputs, even when only one of them was observed.

In one line: stop storing one answer per state, start storing a function that produces answers. A 100×100 grid with 4 actions needs 40,000 stored numbers; a network with 4,096 weights answers all 40,000 questions and every question in between.

Q(s,a) → Q_θ(s,a)

Stop storing one answer per state; fit a function whose parameters θ answer every pair, seen or not.

How it actually works

Seven parts follow. Each one is a mechanism, and each depends on the part above it.

Part 1 — One slot per state–action pair

Tabular Q-learning keeps one cell per state–action pair and writes an estimate into it. Learning is a write: compute the target, move that cell a fraction of the way toward it, leave every other cell alone. Why this part exists: the fixed address makes an update exact — with no slot per pair, one experience could not be attributed to one cause.

Part 2 — Count the slots first

The cost is |S| × |A| numbers. A 5×5 grid with 4 actions needs 25 × 4 = 100; a 100×100 grid needs 10,000 × 4 = 40,000, which is 320 KB at 8 bytes each. Pixels end the argument: a 210×160 colour frame at 256 levels holds 256100,800 distinct states, because 210 × 160 × 3 = 100,800. Why this part exists: this arithmetic is the whole case for approximation.

Part 3 — Replace the table with a function

Write Q_θ(s,a): a function with parameters θ that returns a number for any pair you hand it. A linear model is Q(s) = w·s; a network stacks such layers. Nothing is stored per state — the answer is computed on demand from θ. Why this part exists: a computed answer exists for unseen states, so one visit informs the neighbours.

Part 4 — Regress on a target you build

Supervised learning needs labels; RL supplies none, so you build one: y = r + γ max Q_θ(s′,a′), reward plus the discounted best value of the next state. The loss is (y − Q_θ(s,a))², and one gradient step nudges θ toward y. Why this part exists: no target means no error, and no error means nothing to differentiate.

Part 5 — The target moves with you

y is made of Q_θ — the very θ the update is about to move. With r = 1, γ = 0.9 and max Q(s′) = 2.0 the target is 2.8; the step lifts Q(s,a), and shared weights may lift Q(s′) to 2.2, dragging that target to 2.98. Why this part exists: seeing the target move stops you expecting the tidy loss curve of supervised learning.

Part 6 — Generalisation cuts both ways

Because outputs vary smoothly with inputs, one update shifts every nearby state's prediction. Good when neighbours behave alike, bad when they do not: two states with nearly identical features, needing 2 and 8, settle near 5 and never separate. Why this part exists: that is catastrophic interference, invisible in a table and easily misread as an optimiser bug.

Part 7 — The deadly triad

Sutton and Barto's triad is function approximation, bootstrapping, and off-policy data. Any two are safe; all three can diverge, because the moving target is steered by data from a policy you no longer follow. Why this part exists: it says which two you may keep, and therefore which of the topic 24 fixes you need.

What to notice. The 100×100 grid is not the problem — 320 KB fits in a phone. Coverage is. At 60 frames per second, one hour of play is only 60 × 3,600 = 216,000 frames, and 90% of a 10,000-state grid needs 9,000 distinct visits before any cell is trained twice. Memory scales with the state space; experience does not, which is why the failure looks like a wall-colliding agent rather than a crash.

3. Two states that collide

States A and B produce nearly the same features, so the network emits one value for both. A needs 2, B needs 8. Squared error is the training signal, so try three candidate outputs:

Better parameters cannot fix it, because the input holds nothing that separates A from B. Only richer features can, and that is a design decision.

The trap

Most common wrong mental model

"A neural network is just a big table with better memory." It feels right because both map a state to a number, and a network is bigger. But a table claims nothing about unvisited states; a network does, and that claim is an assumption of smoothness built into its architecture.

If the true value function jumps — a cliff worth −100 one cell from a corridor worth +1 — the network averages across the jump and represents neither side. You call it underfitting and add layers, which makes the smooth fit smoother still.

Correction: approximation buys coverage of unseen states at the cost of a smoothness assumption and the tabular convergence proof. Neither returns with more training; both return with better features or with the engineering in topic 24.

The tell: training loss falls on visited states while the policy still fails at one specific pair you can name, and the loss flattens at a nonzero floor that more epochs never cross. The second tell is a reward curve that climbs for two million steps then collapses — divergence, not a plateau, and the signature of the triad rather than of a bad learning rate.

Retrieval check

  1. Why is a table impossible for a camera-based robot?
    Answer

    The state is a high-dimensional image, so |S| is astronomically large. No table of that size can be stored, and most states would never be visited anyway.

  2. Name the three ingredients of the deadly triad.
    Answer

    Function approximation, bootstrapping (using estimated values as targets), and off-policy training. Any two are stable; all three can diverge.

  3. Why does approximation break the i.i.d. assumption that supervised learning relies on?
    Answer

    Transitions arrive in temporal order from the current policy, so consecutive samples are highly correlated and the data distribution shifts as the policy improves.
