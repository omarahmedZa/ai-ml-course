Privacy & threat model

You can explain DP noise, secure aggregation, and poisoning/backdoor attacks.

Why this matters

Federated learning is often sold as "private by default". It is not: a gradient can be inverted into a recognisable image. This topic is the difference between a privacy claim and a privacy mechanism.

The one core idea

Federated learning protects data locality, not data secrecy. Privacy requires an additional mechanism that bounds what any single update reveals.

How it actually works

ThreatMechanismDefence
Membership inferenceOverfitting makes seen examples more confidentRegularisation, DP
Gradient inversionOptimise a dummy input to match the observed gradientDP-SGD, secure aggregation
PoisoningMalicious client sends a corrupted updateRobust aggregation (median, trimming)
BackdoorTrigger pattern → attacker-chosen labelUpdate inspection, clipping, DP
  • Differential privacy: a randomised mechanism M is (ε, δ)-DP if for any two datasets differing in one record, P(M(D) ∈ S) ≤ e^ε P(M(D′) ∈ S) + δ. ε is a budget: smaller means more privacy and more noise.
  • DP-SGD: clip each per-example gradient to norm C, sum, add Gaussian noise N(0, σ²C²). Clipping bounds sensitivity; noise hides the contribution.
  • Secure aggregation: clients' updates are summed under cryptographic masking, so the server sees only the sum. Protects against a curious server, not against a malicious client.
  • Privacy budget composition: every round spends ε. 1,000 rounds of ε = 0.01 is not ε = 0.01 overall.

Worked example

1. Clipping and noise

A per-example gradient has norm 10. Clip to C = 1 → multiply by 0.1. Sum over a batch of 256 → each example contributes at most 1, so total sensitivity ≤ 1 (per example). Add noise with σ = 1.1 → the noise standard deviation is 1.1, comparable to one example's contribution.

CσEffect
1.00.5Weak privacy, better accuracy
1.01.1Standard operating point
1.04.0Strong privacy, large accuracy cost

2. Why averaging is not anonymisation

The server sees w_t^k, a deterministic function of client k's data. If that client is the only one with a rare condition, the update is a fingerprint. Gradient-inversion attacks reconstruct recognisable inputs from such updates in a handful of iterations.

The trap

Most common wrong mental model

"Federated = private." Locality removes the data-transfer step, not the information leak. Without clipping, noise, or secure aggregation, the server can read the data out of the gradients.

Second trap: treating DP as free. Every unit of privacy costs accuracy, and the cost compounds across rounds. Choose ε from the threat model, then measure the accuracy you can afford — not the reverse.

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. Why does DP-SGD clip per-example gradients before summing?
    Answer

    To bound sensitivity: one example can change the sum by at most C, regardless of how extreme its gradient is. Noise can then be calibrated to that bound.

  2. Secure aggregation protects against which party, and not which?
    Answer

    It hides individual updates from the server. It does not stop a malicious client from submitting a poisoned update, nor protect the data from that client's own device.

  3. Ten rounds of ε = 0.1. Is the total budget 1.0?
    Answer

    Basic composition gives 1.0 (10 × 0.1); advanced accounting gives somewhat less. Either way the budget grows with rounds — reporting the per-round ε as the total is the standard mistake.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
rng = np.random.default_rng(0)
grad = rng.normal(size=100) * 10              # one example's gradient
C = 1.0
norm = np.linalg.norm(grad)
clipped = grad * min(1.0, C / norm)
print(f"norm {norm:.2f} -> clipped norm {np.linalg.norm(clipped):.2f}")
