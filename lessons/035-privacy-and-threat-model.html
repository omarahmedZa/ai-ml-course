Privacy & threat model

You can explain DP noise, secure aggregation, and poisoning/backdoor attacks.

Why this matters

Every organisation that trains on personal data eventually has to write a sentence a lawyer, an auditor or a regulator will read: "this model was trained without exposing individual records." It is also about three claims you will be asked to defend: that a single update does not reveal its example, that the server cannot read a device's contribution, and that one hostile client cannot rewrite the model.

In an exam the question is "does federated learning guarantee privacy?" and "yes, the data never leaves the device" earns one mark out of five; the rest comes from saying what still leaks and which mechanism bounds it. In a project the same gap is expensive: a team ships a "privacy-preserving" prototype, someone runs a published gradient-inversion script on a captured update, and a face appears. The code was correct; nobody had written down an adversary or a budget.

The one core idea

Think of a locked suggestion box with a translucent slot. Posting your note through the slot guarantees the collector never visits your house — and guarantees nothing about whether the note can be read through the slot. Federated learning builds the box; privacy engineering decides how opaque the paper is.

In one line: locality hides where the data is, while privacy hides what the update says about it. A gradient with norm 10 is a fingerprint of one example; clipping it to C = 1 and adding noise of scale σC = 1.1 is what turns an unbounded leak into a measured one.

How it actually works

Six parts, in the order you should reason about them: adversary, leak, bound, noise, cryptography, accounting.

Part 1 — Name the adversary first

Privacy claims are meaningless until you say who is attacking. The three standard adversaries are the honest-but-curious server, a malicious client in the fleet, and anyone watching the network; each sees a different thing.

Why this part exists: without a named adversary, "private" cannot be tested or falsified, and a design that defeats the wrong attacker ships with a false sense of safety.

Part 2 — An update is a function of the data

A gradient is computed from rows, so it carries information about them: a 100-dimensional update from one example is 100 numbers constrained by that example. Gradient inversion searches for an input whose gradient matches the observed one.

Why this part exists: this is the structural leak that locality does not touch; if updates did not depend on the data there would be nothing to protect and no field to study.

Part 3 — Clipping bounds the sensitivity

Take each per-example gradient, measure its norm, and if it exceeds C scale the whole vector down to length C. A gradient of norm 10 clipped at C = 1 is multiplied by 0.1; the direction survives, the size is capped.

Why this part exists: differential privacy calibrates noise to the worst case a single record can cause, and an uncapped record makes that worst case unbounded — no finite amount of noise could hide it.

Part 4 — Noise is calibrated to that bound

Add Gaussian noise with standard deviation σC to the clipped sum; with C = 1 and σ = 1.1 the noise standard deviation is 1.1. The guarantee is a ratio of probabilities, so the noise must be comparable to the largest contribution it hides. Bigger σ means smaller ε and less accuracy.

Why this part exists: clipping alone is not privacy — a clipped vector still points at its example — so the noise is what converts a bounded leak into a probabilistic one.

Part 5 — Secure aggregation hides the individual vector

Clients add random masks that cancel when summed, so the server receives only the total and never an individual update; with 1,000 clients it sees one sum instead of 1,000 vectors. That complements DP rather than replacing it, since the total is still a function of everyone's data, and it protects the curious server — not a client's own device and not the model's integrity.

Why this part exists: differential privacy is statistical — enough observations can erode it — and secure aggregation removes the individual observation entirely for the party that runs the round.

Part 6 — Every round spends budget, and averages can be poisoned

Composition is brutal: 1,000 rounds at ε = 0.01 is around 10 under basic composition, not 0.01. Separately, a plain mean is linear, so with 100 clients any single update moves the result by 1% of whatever it sends — and what it sends has no ceiling; median or trimmed-mean aggregation removes that lever.

Why this part exists: a per-round budget is a per-round promise, and an aggregation rule with no robustness is an open door for exactly the adversary named in part 1.

Worked example

1. Clipping one gradient

Clip g = [6, 8] to C = 1, then clip g = [3, 4] the same way. Both are two-dimensional, so the norm is the hypotenuse.

Step[6, 8][3, 4]
Norm √(a² + b²)√(36 + 64) = 10√(9 + 16) = 5
Scale C / norm1/10 = 0.11/5 = 0.2
Clipped vector[0.6, 0.8][0.6, 0.8]
New norm√(0.36 + 0.64) = 1√(0.36 + 0.64) = 1

What to notice. Both vectors land on the same point, so clipping erases the fact that one example was twice as strong. That is the point: no single example can contribute more than 1, the number the noise is calibrated against. It also shows the cost — an unusual example no longer stands out, and that is accuracy you chose to give up.

Holding a total of 1.0 at 0.01 per round caps you at 100 rounds, which is a hard constraint on the training schedule — you must budget rounds like money, before tuning anything else.

Masks must be generated pairwise and cancelled exactly; if one client drops out, the rest no longer sum to zero and the round must restart. That fragility is the price of hiding individual vectors.

The trap

Most common wrong mental model

"Federated means private." It feels right because the data provably never moves and the architecture diagram puts a padlock on every device. Locality is a real property; it is just not the one being claimed.

The update is a compressed picture of the data, and compression is not encryption: a server that stores a thousand rounds has a thousand pictures of the same client. Clipping, noise and secure aggregation each remove one channel, and none of them is implied by the federated loop. A second trap is treating DP as free: every unit of ε buys privacy with accuracy, and the bill compounds across rounds.

Correction: write the claim as a mechanism plus a number — "trained with DP-SGD, ε = 1.0 at δ = 10⁻⁵, secure aggregation over 100 rounds" — and check that each part maps to an adversary you named.

The tell: the word "privacy-preserving" with no ε, no noise scale and no adversary anywhere in the document. The second tell is a single ε quoted for a long run; ask whether it is per round or total, and the answer moves by an order of magnitude. The third is a reconstruction demo that works on the deployed system: there, cryptography was doing the work the statistics was meant to do.

Retrieval check

  1. Why does DP-SGD clip per-example gradients before summing?
    Answer

    To bound sensitivity: one example can change the sum by at most C, regardless of how extreme its gradient is. Noise can then be calibrated to that bound.

  2. Secure aggregation protects against which party, and not which?
    Answer

    It hides individual updates from the server. It does not stop a malicious client from submitting a poisoned update, nor protect the data from that client's own device.

  3. Ten rounds of ε = 0.1. Is the total budget 1.0?
    Answer

    Basic composition gives 1.0 (10 × 0.1); advanced accounting gives somewhat less. Either way the budget grows with rounds — reporting the per-round ε as the total is the standard mistake.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
rng = np.random.default_rng(0)
grad = rng.normal(size=100) * 10              # one example's gradient
C = 1.0
norm = np.linalg.norm(grad)
clipped = grad * min(1.0, C / norm)
print(f"norm {norm:.2f} -> clipped norm {np.linalg.norm(clipped):.2f}")
