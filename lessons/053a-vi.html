γ (gamma) — what one sweep is worth

You can run a value-iteration sweep by hand on three states, and say when γ changes the answer rather than the speed.

Where this sits

V(s) ← maxa Σ p(s′|s,a)[ r + γ V(s′) ]

Topic 53 · only γ is lit; r is the reward on the transition and p is the transition probability

The backup reads the value of the next state, adds the reward on the way there, and multiplies the future by γ. Apply it to every state at once and you have one sweep of value iteration. Start from zeros and repeat; when γ < 1 the values settle on a fixed point.

Three states, one sweep

The chain is A → B → C, with C terminal and worth 0. At A there is a shortcut to B paying 0 and a scenic route straight to C paying 0.5. At B, go reaches C and pays 1. Every transition is certain, so each probability is 1.

Take γ = 0.9 and start with every value at 0. Sweep 1: B pays 1 and then ends, so V(B) = 1 + 0.9 × 0 = 1. At A the shortcut is worth 0 + 0.9 × 0 = 0 against 0.5 for the scenic route, so V(A) = 0.5. Sweep 2 rereads the values just written: the shortcut is now 0.9 × 1 = 0.9, which beats 0.5, so V(A) rises to 0.9. Sweep 3 changes nothing.

Each sweep carries value back exactly one transition. Sweep 1 lets B see the reward at the end of its own edge; sweep 2 lets A see B's new value. A longer chain would take one sweep per edge, and every extra edge costs another factor of γ.

The curve is also a picture of patience: near 1 the agent will wait for the distant reward; near 0.5 it takes whatever pays now.

The discount decides the action

At A the two actions can be compared directly. The shortcut is worth γ × V(B) = γ × 1, because B is worth 1 and one step of delay is priced at γ. The scenic route pays 0.5 immediately. So the choice depends only on whether γ is above or below 0.5.

Nothing about the states, actions or rewards changed. γ moved one comparison and the policy moved with it — the discount is an input to the answer, not a solver setting.

The trap— γ

Most common wrong mental model

"γ only affects how fast value iteration converges." It does change the speed — a γ near 1 needs many more sweeps — but it also moves the fixed point. Change γ and the values converge to different numbers, and at A the policy flips.

Correction: read γ as part of the task, written beside the reward. More sweeps cannot repair a discount that priced the future at the wrong rate; they converge harder to the answer γ asked for.

The tell: the values settle tidily, the sweep count is small, and the agent still behaves myopically. That is not a convergence bug — check γ, and check which transition the reward sits on.

Retrieval check— γ

  1. With γ = 0.4, which action does A prefer, and why?
    Answer

    The scenic route. The shortcut is worth 0.4 × 1 = 0.40, while the scenic route pays 0.5 immediately. The 1 at B is still there, but at this discount it arrives too late to beat half a point now.

  2. After two sweeps at γ = 0.9, V(A) = 0.9 and V(B) = 1.0. Why is V(A) not also 1.0?
    Answer

    The 1 is collected on the edge from B to C, one transition beyond B. From A that reward has one step of delay, so it enters as γ × 1 = 0.9. V(B) is 1.0 because B is standing on the paying edge.
