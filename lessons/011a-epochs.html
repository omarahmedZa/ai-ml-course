Equation lab · the training loop

Steps, batches, epochs — three words, one division

You can convert a dataset and a batch size into a count of weight updates, and say why an epoch count alone means nothing.

Where this sits

updates = epochs × n / batch = epochs × steps per epoch

Lab 1 of 1 · the division is lit; epochs only multiply what one pass already produced

Three words get used as if they were one. A step is one weight update. A batch is the group of rows that produces it. An epoch is one full pass over the data. Only the step changes a weight, so only the step is a unit of learning.

The division

The dataset has 10,000 rows. Cut it into batches of 50 and you get 200 slices, so one epoch contains 200 steps. Batch 100 gives 100 steps; batch 500 gives 20. Bigger batches mean fewer, larger steps, because each step consumes more rows.

Epochs multiply

One epoch is one pass, so the update count is the step count times the number of passes. Twenty epochs at batch 100 is 2,000 updates. The same twenty epochs at batch 500 is 400. Same data, same epochs, five times fewer chances to correct the weights.

What the trade is

A small batch gives many noisy steps: few rows per gradient, so it jumps but corrects often. A large batch gives few smooth steps: a quieter average, more memory, fewer chances to fix a mistake. Neither is free, which is why batch size is a real decision and not a formatting detail.

Check the hidden count

320. First the division: 10,000 / 250 = 40 steps per epoch. Then the multiplication: 40 × 8 = 320 updates. Do them in that order; multiplying the epoch count first gives the wrong shape of answer.

The trap

Most common wrong mental model

"Twenty epochs means twenty units of training, whatever the batch size." It feels right because the epoch is the word people report, and the loss curve is usually drawn against it.

Correction: an epoch is a pass, not an update. Batch size decides how many updates fit inside that pass, so two runs with the same epoch count can differ tenfold in how often the weights moved.

The tell: hold the epochs fixed and change the batch from 100 to 1,000. The update count falls tenfold and the curve has a tenth as many points. If the reported "training" is unchanged, the report is counting passes, not steps.

Retrieval check

  1. 10,000 rows, batch 250, eight epochs. How many updates?
    Answer

    320. 10,000 / 250 = 40 steps per epoch, then 40 × 8. Two operations, in this order.

  2. Same 20 epochs, batch 50 or batch 500. Which run takes more steps?
    Answer

    Batch 50: 4,000 updates against 400. The small batch takes ten times as many steps over the same number of passes.
