Attribution, one symbol at a time · Lab 1

φ — a fair share of the prediction

You can compute a Shapley value for two features by averaging their marginal gain over every ordering.

Where this sits

f(x) = φ0 + φ1 + φ2 = 1.0

Lab 1 of 3 · the shares are lit; the baseline and the total are dimmed

SHAP asks one question about one prediction: how much of it belongs to each feature? φ (phi) is one feature's answer. The shares plus the baseline φ0 must rebuild the output exactly, so φ is a split, never a score on its own.

The game

Write v(S) for the model's score when only the features in set S are switched on. v(∅) = 0 is the baseline — no features, no signal. With two features there are four coalitions to score.

Coalition SFeatures presentScore v(S)
∅none0
{1}feature 1 only0.6
{2}feature 2 only0.4
{1,2}both1.0

Here the two singles happen to add to the pair. That is a coincidence of these numbers, and the faded example below breaks it on purpose.

Two orderings, one average

A feature's marginal gain depends on who arrived first. Add the features one at a time and read off what each addition was worth.

OrderingGain for feature 1Gain for feature 2
1 then 20.6 − 0 = 0.61.0 − 0.6 = 0.4
2 then 11.0 − 0.4 = 0.60.4 − 0 = 0.4
averageφ₁ = 0.6φ₂ = 0.4

Both orderings agree here, so the average is easy: 0.6 and 0.4. The averaging is the point. Each ordering pays a feature for the moment it arrived, and no feature is punished for arriving late.

Why average orderings

With two features there are only two orderings; with ten there are 3,628,800, which is why real SHAP is approximated by sampling. The average is worth remembering for three properties: a useless feature earns zero, identical features split evenly, and the shares always sum to the total.

Faded example

Same game, new scores: v(∅) = 0, v({1}) = 0.3, v({2}) = 0.5, v({1,2}) = 1.0. Now the singles add to 0.8, not 1.0, so the two orderings disagree and the average has real work to do.

Check the last two rows

Feature 1 arriving second gains 1.0 − 0.5 = 0.5. So φ₁ = (0.3 + 0.5)/2 = 0.4 and φ₂ = (0.7 + 0.5)/2 = 0.6. Sum 1.0, as it must be.

The trap

Most common wrong mental model

"φ₁ = 0.6 means feature 1 caused 60% of the decision." It means feature 1 is worth 0.6 in this game, against this baseline, with this rule for what "present" means. Move the baseline and every φ shifts while the prediction stays put.

Correction: read φ as a share of one prediction under stated assumptions. Two correlated features divide one effect between them, so both look harmless and the real driver disappears from the chart.

The tell: add a duplicate column carrying the same feature. The prediction does not move, but the original column's φ falls by about half. Credit was divided, not earned — and no number tells you that happened.

Retrieval check

  1. With v(∅) = 0, v({1}) = 0.2, v({2}) = 0.7 and v({1,2}) = 1.0, what are φ₁ and φ₂?
    Answer

    Order 1 then 2 gives 0.2 and 0.8; order 2 then 1 gives 0.7 and 0.3. Averaging: φ₁ = 0.45, φ₂ = 0.55. They sum to 1.0.

  2. Why must the two shares add to the output rather than to zero?
    Answer

    Because φ₀ is the baseline, not zero credit. Baseline plus all shares reconstructs f(x); that property is what makes the list trustworthy as a decomposition.
