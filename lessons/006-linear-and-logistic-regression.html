Linear & logistic regression

You can derive a logistic decision boundary, and say why squared error is the wrong loss for classification.

Why this matters

These are the baselines every project must beat before deep learning is justified, and logistic regression is literally the last layer of every classifier in Unit 7. Same dot product, one extra function.

The one core idea

A linear model computes one weighted sum. The link function decides whether that sum is a prediction (regression) or a probability (classification).

How it actually works

Linear regressionLogistic regression
Scorez = w·x + bz = w·x + b
Outputŷ = z (any real)p = σ(z) ∈ (0,1)

Solved byclosed form or GDgradient descent
σ(z) = 1 / (1 + e⁻ᶻ) boundary: w·x + b = 0
  • z is the logit = log-odds: z = ln(p / (1−p)). The model is linear in log-odds, not in probability.
  • Predict class 1 when p > 0.5, i.e. when z > 0. So the decision boundary is the hyperplane w·x + b = 0 — always straight, no matter how confident the probabilities get.
  • w is the boundary's normal vector; b shifts it. Doubling ‖w‖ does not move the boundary — it only makes probabilities more extreme.

Worked example

1. One point, one probability

w = [1, −1], b = 0, x = [2, 0.5]:

The distance from the boundary controls confidence: z = 0 → p = 0.5; z = 4 → p = 0.982. Points far from the line are not "more correct" — only more confidently classified.

2. Where the boundary sits

With two features and w = [1, −2], b = 1, the boundary is x₁ − 2x₂ + 1 = 0, i.e. x₂ = 0.5x₁ + 0.5 — a line with slope 0.5. Everything above it is class 0; below, class 1. If the true boundary is curved, no choice of w will fix it: that is where hidden layers enter (Unit 2).

The trap

Most common wrong mental model

"Use squared error, it worked for regression." For classification it is a bad objective: the sigmoid saturates, the gradient vanishes exactly when the model is most wrong, and the loss is non-convex in w. Cross-entropy is the correct likelihood (topic 3) and has a clean gradient, (p − y)x.

Second trap: judging it by accuracy on imbalanced data. 99% accuracy on 1% positives is achieved by predicting "no" forever. Use precision, recall, or AUC — and always compare to that trivial baseline.

Step by step

If the mechanism above went past you, walk it one click at a time. Each step is one sentence and one idea.

Retrieval check

  1. With w = [2, 1], b = −3, classify x = [1, 1] and give its probability.
    Answer

    z = 2 + 1 − 3 = 0, so p = 0.5 — the point sits exactly on the boundary. Not a confident prediction; a tie.

  2. Why does scaling w by 10 not move the decision boundary?
    Answer

    The boundary is where w·x + b = 0. Scaling w scales both sides, so the set of solutions is unchanged. It only steepens the sigmoid, pushing probabilities toward 0 and 1.

  3. Your classifier reports 97% accuracy on a dataset with 3% positives. What is the trivial baseline, and what should you report instead?
    Answer

    Always predicting "negative" scores 97%. Report precision, recall, and AUC against that baseline; 97% may mean the model learned nothing.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
rng = np.random.default_rng(0)
X = rng.normal(size=(50, 2))
true = np.array([2., -3.])
y = X @ true + 1 + rng.normal(0, .1, 50)
A = np.c_[X, np.ones(50)]
coef, *_ = np.linalg.lstsq(A, y, rcond=None)
