Linear & logistic regression

You can derive a logistic decision boundary, and say why squared error is the wrong loss for classification.

Why this matters

These are the baselines every project must beat before deep learning is justified, and logistic regression is literally the last layer of every classifier in Unit 7. Same dot product, one extra function. A linear model predicts a quantity — tomorrow's demand, a house price, a dose. A logistic model predicts a probability — will this customer default, is this scan abnormal — and thresholds it into yes or no. Between them they cover most tabular problems you will meet, and a stack of fifty neural layers still ends in σ(w·x + b).

The failure it prevents. An exam question gives w = [1, −2], b = 1 and asks where the boundary sits and which side is class 1. Students who read the output as a score draw the line correctly and then label both sides backwards, because the boundary is z = 0, not p = 0. In a project the same confusion ships a classifier reporting 97% accuracy on data with 3% positives — it answers "no" to every row and the metric never notices.

The one core idea

Both models are a single weighted sum, w·x + b. What changes is the last step: linear regression hands that sum out unchanged, while logistic regression pushes it through a squashing function so it lands between 0 and 1. Same engine, different gauge on the dashboard — and the gauge decides what the number is allowed to mean.

In one line: one weighted sum, then a link function that says whether it is a quantity or a probability. With w = [1, −1], b = 0 and x = [2, 0.5], the score is 2 − 0.5 = 1.5; read raw that is 1.5 units, read through the sigmoid it is a probability of 0.818.

How it actually works

Six parts, from the sum itself to the algorithm that finds its weights.

Part 1 — One weighted sum is the whole model

z = w·x + b, with one weight per feature and one bias. A 2-feature classifier stores exactly 3 numbers, and every prediction is arithmetic on those 3. Interpretability comes free: a weight of 2 means one more unit of that feature adds 2 to the score.

Why this part exists: without the bias, every boundary is forced through the origin, so a model could not express a dividing line sitting at x₂ = 0.5x₁ + 0.5.

Part 2 — The link decides what the score means

Linear regression uses the identity link, so ŷ = z and any real value is allowed. Logistic regression uses the sigmoid σ(z) = 1/(1 + e⁻ᶻ), which maps the whole real line into (0, 1) and equals 0.5 at z = 0. Choosing the link is choosing whether the output is a quantity or a probability.

Why this part exists: an identity link on a probability task returns values like −0.4 or 1.7, which no likelihood can score and no threshold can interpret.

Part 3 — The score is log-odds, not probability

Solving the sigmoid for z gives z = ln(p/(1−p)), the log-odds. A probability of 0.8 means odds of 4:1, so z = ln 4 = 1.386. The model is therefore linear in log-odds, and equal steps in z multiply the odds by the same factor — the arithmetic of evidence that accumulates additively.

Why this part exists: treating z as a probability puts the boundary at 0.5 instead of 0 and makes every later geometric statement wrong.

Part 4 — The boundary is where the score is zero

Predict class 1 when p > 0.5, which happens exactly when z > 0. So the decision boundary is w·x + b = 0, a hyperplane — the flat surface a straight boundary makes — whose normal vector is w, and it stays straight however confident the probabilities become. Distance from the plane sets confidence; it never changes the label.

Why this part exists: half the marks in this topic live here, and scaling w by 10 leaves the boundary fixed while pushing probabilities to the extremes.

Part 5 — Match the loss to the output type

Squared error is right for a quantity and wrong for a probability. Binary cross-entropy, −[y ln p + (1−y) ln(1−p)], is the likelihood from topic 3, and its gradient with respect to the score is simply (p − y) — large when the model is wrong, zero when it is right.

Why this part exists: put a sigmoid in front of squared error and the gradient fades exactly when the prediction is most wrong, so training stalls at whatever random weights it started from.

Part 6 — Solve, knowing there is one valley

Linear regression has a closed form, θ = (XᵀX)⁻¹Xᵀy. Logistic regression has none, because the sigmoid makes the equations non-linear, so gradient descent updates w ← w − η(p − y)x. Both objectives are convex, so each has a single minimum.

Why this part exists: knowing the surface has one valley tells you a stalled loss is a learning-rate bug, not a second valley worth exploring.

The trap

Most common wrong mental model

"Use squared error — it worked for regression." It feels right because it is the loss you already know, it does decrease at first, and every library offers it, so nothing raises an error. But with a sigmoid in front, squared error is non-convex and its gradient shrinks to almost nothing exactly where the prediction is most wrong: the model sits at 0.49 for a clear positive and barely moves.

Correction: the output type picks the loss. A quantity wants squared error; a probability wants binary cross-entropy, which is the negative log-likelihood and whose gradient stays large under exactly the mistakes you care about. Underneath sits a second, quieter assumption — that accuracy is a fair score — and on imbalanced data it is not.

The tell: a loss curve that is flat from the first epoch while accuracy sits at the majority-class rate, or predicted probabilities bunched near 0.5 with no confident values anywhere. The other tell is a reported accuracy that exactly equals the fraction of the majority class, to the decimal — always compare against that number before celebrating.

Retrieval check

  1. With w = [2, 1], b = −3, classify x = [1, 1] and give its probability.
    Answer

    z = 2 + 1 − 3 = 0, so p = 0.5 — the point sits exactly on the boundary. Not a confident prediction; a tie.

  2. Why does scaling w by 10 not move the decision boundary?
    Answer

    The boundary is where w·x + b = 0. Scaling w scales both sides, so the set of solutions is unchanged. It only steepens the sigmoid, pushing probabilities toward 0 and 1.

  3. Your classifier reports 97% accuracy on a dataset with 3% positives. What is the trivial baseline, and what should you report instead?
    Answer

    Always predicting "negative" scores 97%. Report precision, recall, and AUC against that baseline; 97% may mean the model learned nothing.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
rng = np.random.default_rng(0)
X = rng.normal(size=(50, 2))
true = np.array([2., -3.])
y = X @ true + 1 + rng.normal(0, .1, 50)
A = np.c_[X, np.ones(50)]
coef, *_ = np.linalg.lstsq(A, y, rcond=None)
