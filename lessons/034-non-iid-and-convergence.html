Non-IID data & client drift

You can explain client drift, name the fixes, and state the local-steps trade-off.

Why this matters

Every FL tutorial uses MNIST split evenly across clients. Real deployments never look like that — one phone belongs to a teenager, another to a radiologist. This gap is where federated models quietly underperform.

The one core idea

When clients' data distributions differ, local training pulls each client's weights toward its own optimum. Averaging those divergent models gives a point that is optimal for nobody — client drift.

How it actually works

  • Label skew: client A only sees digit 3, client B only digit 7. Each local model becomes confidently wrong about the other 8 classes.
  • Feature skew: same task, different sensors — different scales, noise, or lighting.
  • Quantity skew: 10 examples versus 100,000, which also tilts the weighted average.
  • Drift grows with E: more local epochs means each client travels further toward its private optimum before the average.
  • FedProx: add a proximal term (μ/2)‖w − w_t‖² to each local objective, anchoring clients near the global model. μ controls the leash.
  • Personalisation: accept that one global model is the wrong goal — train a shared representation and fine-tune per client, or keep some layers local (FedBN).
  • Fairness: the global model can be accurate on average and terrible for small clients. Report per-client accuracy, not just the mean.
local objective: F_k(w) + (μ/2)‖w − w_t‖²

Worked example

1. The local-steps trade-off

The average is unchanged, but the clients have each become specialists. On a third client with mixed data, the averaged model is worse than either specialist — this is drift, not convergence.

2. Why "more local work" is not free

Local epochs reduce communication rounds (good) while increasing drift (bad). FedProx makes the trade explicit: with μ > 0, clients can take more steps without wandering, because every step pays a penalty for leaving w_t.

The trap

Most common wrong mental model

"More local epochs always improve communication efficiency." They reduce rounds but increase client drift, and beyond a small E the global model degrades. The optimum is empirical, not monotone.

Second trap: evaluating on a pooled test set only. A model can be excellent in aggregate and useless for the smallest client — exactly the user the deployment was meant to serve.

Retrieval check

  1. What is client drift, in one sentence?
    Answer

    Local updates move each client's weights toward its own data distribution, so the averaged global model sits in a region that is optimal for no client.

  2. What does the proximal term in FedProx do as μ increases?
    Answer

    It penalises distance from the global weights more heavily, shrinking each client's step toward its local optimum. Large μ behaves more like federated SGD.

  3. Why might per-client accuracy be the right metric instead of the global average?
    Answer

    Because FL is usually deployed to serve each client. A high mean can hide a small or unusual client being systematically misclassified — a fairness failure invisible in aggregate.
