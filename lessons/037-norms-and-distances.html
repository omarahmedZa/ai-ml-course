Norms & distances

You can compute L1, L2 and max distances on real numbers, say what each one measures, and explain when standardising features changes the answer.

FoundationsLinear Algebra

Why this matters— the shape of distance

Every nearest-neighbour search, clustering run and embedding comparison comes down to one question: how far apart are two points? The answer is never neutral. The rule you choose decides which items count as similar, and in a model with mixed units it can decide the output. A recommender that says two films are close, a fraud system that flags an outlier, a vector database returning ten documents — each is a norm wearing different clothes.

The failure it prevents. A housing model compares area in square feet with price in pounds. Price differs by hundreds of thousands while area differs by hundreds, so Euclidean distance is almost entirely price. The model looks reasonable and quietly ignores the feature you cared about.

The one core idea— the shape of distance

A norm turns a vector into a single non-negative number that says how big it is. Write it ‖v‖ with double bars. It must be zero only for the zero vector, it must scale with the vector, and it must obey the triangle inequality: going straight from A to C is never longer than going through B.

A distance between two points is the norm of their difference: d(a,b) = ‖a − b‖. So the whole subject reduces to picking a norm, subtracting, and measuring.

Three norms cover most practice. L2 squares each entry, adds, and takes the root — straight-line length. L1 adds absolute values — the distance a taxi drives on a grid. L∞ takes the largest absolute entry — the worst single feature. For v = (3,4): L1 is 7, L2 is 5, L∞ is 4.

d(a,b) = ‖a − b‖₂  ·  ‖v‖₁ = Σ|vᵢ|  ·  ‖v‖∞ = max|vᵢ|

Same points, three answers. The norm is a modelling choice, not a fact.

How it actually works— the shape of distance

Part 1 — The L2 norm and straight-line distance

For a = (1,2) and b = (4,6), subtract to get a − b = (−3,−4). Square each entry: 9 and 16. Add: 25. Take the root: 5. That is Pythagoras applied one coordinate at a time, and it is the distance a ruler would measure on a flat page.

Why this matters: L2 is differentiable and rotation-invariant, so least squares and PCA use it; but squaring lets one huge coordinate dominate.

Part 2 — The L1 norm and grid distance

For the same pair, add absolute differences: 3 + 4 = 7. This is the distance a taxi travels on a street grid, or the number of edits between two strings when each edit changes one symbol. It never discounts a large difference the way squaring does; every unit counts once.

Why this matters: L1 resists wild coordinates and produces sparse solutions, so it sits behind Lasso.

Part 3 — The L∞ norm and worst-case distance

For the same pair, the largest absolute difference is 4. This asks a different question: not "how much error in total" but "how bad is the single worst feature". A factory checks every dimension this way — one part outside tolerance fails the batch, no matter how good the others are.

Why this matters: when a guarantee must hold feature by feature, an average hides the violation.

Part 4 — Cosine similarity and standardisation

Sometimes direction matters and length does not. Two documents about the same topic should be close even if one is ten times longer. Cosine similarity divides the dot product by both lengths: cos(a,b) = (a·b)/(‖a‖₂‖b‖₂). It runs from −1 to 1, and the angle between the vectors is arccos of it. For a = (1,0) and b = (1,1): dot 1, lengths 1 and 1.414, so cosine 0.707 and angle 45°.

Standardisation rescales each column to mean 0 and spread 1 before measuring: z = (x − mean)/sd. No column then wins by being recorded in smaller numbers.

Read it as a sentence. The points sit 5 units apart in a straight line, 7 along a grid, and differ by at most 4 in any one coordinate. Cosine says 1.00 because b is exactly a doubled — same direction, different length. If your task is "are these the same topic", cosine calls them identical; if it is "are these the same size", it says nothing at all.

2. Why the answer changes with units

Take area in hundreds of square feet and price in hundreds of thousands of pounds: p = (1,2), q = (2,1). L2 distance is √2 = 1.414. Record price in pounds instead and the second coordinate becomes 200,000 against 100,000, so the distance is √(1 + 10¹⁰) ≈ 100,000. The area difference of 1 is invisible.

Standardise first. If area has mean 1.5 and spread 0.5, the values become −1 and +1. If price has mean 150,000 and spread 50,000, it also gives +1 and −1. The difference is now (−2,2), L2 distance √8 = 2.83, and both features count equally.

3. When L1 and L2 disagree about the nearest neighbour

Query q = (0,0), candidates p = (3,3) and r = (0,5). L2 puts p at √18 = 4.24 and r at 5, so p is nearer. L1 puts p at 6 and r at 5, so r wins. L∞ puts p at 3 and r at 5, so p wins. Only the norm changed.

The trap— the shape of distance

Most common wrong mental model

"Distance is a property of the data." Distance is a property of the data plus the norm plus the units. Euclidean distance feels like the neutral default because it matches the page, but the page is not the model's world.

Adding a copy of one feature, measured in millimetres instead of metres, multiplies that direction's contribution by 1,000. The points have not moved; the geometry has.

Correction: fix the units and name the norm before computing. Standardise columns with no shared scale; use L1 when outliers must not dominate, L∞ for worst-case error, cosine when only direction matters.

The tell: the nearest neighbour changes when you convert a column's units or add a duplicate column. Both are unit bugs. Compute the distance on raw and standardised columns and compare the neighbour lists.

Retrieval check— the shape of distance

  1. Compute all three norms of (−6,8).
    Answer

    L1 is 6 + 8 = 14; L2 is √(36 + 64) = 10; L∞ is max(6,8) = 8. The signs vanish because every norm uses absolute value or a square.

  2. Two vectors point in exactly opposite directions. What is their cosine similarity, and what are their L2 and L1 distances if both have length 1?
    Answer

    Cosine is −1. Their difference has length 2, so L2 distance is 2 and L1 distance is 2 as well — for opposite unit vectors the two norms agree.

  3. A colleague standardises the features and then reports that L1 and L2 give the same neighbour. Is that a contradiction?
    Answer

    No. Standardising changes the geometry, and different norms can agree on a particular dataset. The norms still define different balls; the points just happen to fall where the answers coincide.

Solve it · 037 — Three distances, one function

Build it in Colab— the shape of distance

Runnable, NumPy-only: open the notebook in Colab · local copy. It draws the unit balls and shows a neighbour flipping after standardisation.

import numpy as np
a,b = np.array([3.,4.]),np.array([6.,8.])
d = a - b
print(np.abs(d).sum())          # L1 = 7.0
print(np.linalg.norm(d))        # L2 = 5.0
print(np.abs(d).max())          # L∞ = 4.0
