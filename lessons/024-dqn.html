DQN: two fixes that made it work

You can explain replay buffer and target network as fixes for correlated data and moving targets.

Why this matters

DQN is the canonical example of "the algorithm was known for decades; the engineering made it work". It is also the cleanest exam question in Unit 6: name the two tricks and the problem each solves.

The one core idea

Q-learning with a neural network fails for two concrete reasons — correlated samples and a target that moves with the weights. Replay buffer fixes the first; target network fixes the second.

How it actually works

ProblemFixMechanism
Consecutive frames are nearly identical → gradients chase one trajectoryReplay bufferStore 10⁶ transitions; sample random minibatches. Restores approximate i.i.d.
Target r + γ max Q_θ uses the weights being updated → chasing a moving targetTarget networkCopy θ⁻ ← θ every ~10k steps; compute targets with the frozen copy
Large TD errors dominate the lossHuber lossQuadratic near 0, linear beyond — robust to outliers
Overestimation from max over noisy estimatesDouble DQNSelect with θ, evaluate with θ⁻
L(θ) = E[( r + γ max_{a′} Q_{θ⁻}(s′,a′) − Q_θ(s,a) )²]
  • Behaviour vs target policy: acting uses ε-greedy on Q_θ; learning uses the frozen target. Off-policy is what makes the buffer legal.
  • ε decay: 1.0 → 0.1 over the first million frames. Random data early is what fills the buffer with variety.
  • Frame stacking (4 frames) gives the network velocity — a single frame cannot distinguish "moving left" from "moving right".

Worked example

1. Why the target network matters, numerically

Suppose Q_θ(s,a) = 0.5 and the target is 1 + 0.9·max Q_θ(s′,·) = 1.72. One gradient step raises Q_θ(s,a) toward 1.72 — but it also raises Q_θ(s′,·), so the target for the next update has moved. With a frozen target, the target stays 1.72 for 10,000 steps and the update is a stable regression. That is the entire argument.

2. Replay in one line

A buffer of 1,000,000 transitions, minibatch 32. Sampling uniformly means each gradient step sees 32 unrelated moments from thousands of episodes — the opposite of "32 consecutive frames of the same corridor".

The trap

Most common wrong mental model

"Replay buffers are a general RL trick." They require off-policy learning. Put a replay buffer behind REINFORCE or PPO and you are training on data from policies that no longer exist — the importance weights blow up, and the gradient is wrong.

Second trap: believing Double DQN removes overestimation entirely. It reduces the bias from the max; it does not make Q estimates unbiased.

Retrieval check

  1. What does the target network freeze, and for how long?
    Answer

    The weights used to compute max Q(s′,a′). They are copied from the online network every N steps (commonly 10k), then held fixed while the online network trains.

  2. Why does a replay buffer improve sample efficiency?
    Answer

    Every stored transition can be reused in many updates instead of being discarded after one gradient step. It also decorrelates batches, which stabilises the fit.

  3. Why can't PPO use a replay buffer the same way?
    Answer

    PPO is on-policy: its gradient is only valid for data from the current policy. Reusing old-policy data requires importance sampling, and the ratio variance grows quickly with policy drift.

Build it in Colab

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. The cell prints numbers, not pictures — change one value and rerun to see what breaks.

import numpy as np
rng = np.random.default_rng(0)
buffer, r = [], 0.0
for _ in range(1000):
    s = rng.normal(size=4)
    r = 0.9 * r + rng.normal()          # temporally correlated reward
    buffer.append((s, rng.integers(2), r, s + rng.normal(size=4) * .1))
