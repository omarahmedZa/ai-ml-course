Quantization & distillation

You can compute an INT8 scale, bound its rounding error, and explain what a distilled student learns from soft targets.

SystemsSystems

Why this matters— compression

Seven billion weights at four bytes each is 28 GB — bigger than an 8 GB GPU. Quantization stores each weight in one byte, bringing the same model to about 7 GB. Distillation trains a small student to imitate a large teacher, so the artifact that ships is smaller than the teacher.

The failure it prevents. An exam asks "you quantized to INT8, so latency improved fourfold — true?" and "yes" confuses memory with speed: bytes shrink fourfold, but speed depends on kernels and bandwidth. A model compressed to hit a device budget can lose eight points on one segment nobody re-tested.

The one core idea— compression

Compression does not preserve weights; it preserves behaviour on the input distribution. Quantization replaces each float with a small integer plus a scale, so the grid is coarse but the arithmetic is cheap. Distillation trains a student on the teacher's soft outputs — probabilities that say "mostly this, somewhat that".

Both are evaluated the same way: accuracy on held-out slices, latency on the device, memory used. The ratio is a means, never the result.

q = round(w / s), then ŵ = q · s

A scale turns a continuous weight into a grid index and back. The error is bounded by half a grid step.

How it actually works— compression

Six steps: baseline, grid, granularity, calibration, distillation, evaluation.

Part 1 — Measure the uncompressed model first

Record accuracy overall and on the slices you care about, latency on the target hardware, peak memory and artifact size. A compression claim without a baseline is a vibe.

Why: the trade can be good or bad, and you cannot judge it with one side measured.

Part 2 — Build the grid with one scale

For symmetric INT8, take the largest absolute weight max|w| and set s = max|w| / 127. Then q = round(w / s), clamped to [−127, 127], and the restored value is ŵ = q · s.

Why: every stored code is read through the scale, so one bad scale corrupts the whole group.

Part 3 — Choose per-tensor or per-channel

Per-tensor uses one scale for the matrix. Per-channel uses one per output channel, so an outlier no longer stretches the grid for all the others; it costs a few more numbers.

Why: a single weight of 10 makes s large, and every weight near 0.1 then rounds to a handful of codes.

Part 4 — Calibrate, or train through the rounding

Post-training quantization runs representative data through the model to choose activation ranges, then rounds. Quantization-aware training simulates rounding in the forward pass so weights adapt. QAT costs more and usually recovers more accuracy.

Why: activations need ranges too, and a range chosen on wrong data clips the cases you care about.

Part 5 — Distil when the architecture, not just precision, is too big

The teacher produces logits z. Soften them with temperature: softmax(z / T). The student mixes soft targets with true labels, often α · CE(hard) + (1 − α) · T² · KL(soft)(alpha). Higher T exposes more uncertainty about near-miss classes.

Why: hard labels say only "class 3"; soft labels add that class 7 was plausible — supervision the teacher paid to learn.

Part 6 — Evaluate on the device and on slices

Run the compressed model on held-out data, report per-slice accuracy, measure latency with the real runtime, and check memory. A fourfold smaller file the kernel does not accelerate is not a serving win.

Why: compression damage is rarely uniform; it concentrates on rare classes and unusual values, which an aggregate score hides.

Step 1 — check the bound. Half a grid step is s / 2 = 0.0047, and every error above is smaller. That is a bound per weight, not per model: a million small errors still move an activation.

Step 2 — count the memory. One million weights at four bytes is 4 MB; at one byte each they are 1 MB plus a 4-byte scale. The ratio is 4×; the model did not get four times faster.

Step 3 — soften the teacher. Logits [4.0, 1.0, 0.5] at T = 1 give [0.926, 0.046, 0.028]; at T = 2, [0.716, 0.160, 0.124]. The second class rises from 4.6% to 16%.

What to notice. At T = 2 the second and third classes are 16% and 12%; their 1.3-to-1 ratio is the dark knowledge distillation transfers, absent from a one-hot label.

The trap— compression

Most common wrong mental model

"INT8 is four times smaller, so it is four times faster." It feels right because it is the same model at a quarter of the bytes. But speed depends on bandwidth, vector instructions and fast kernels; some layers get slower.

A second version treats distillation as pruning: pruning removes weights from the same architecture, while distillation trains a smaller model to copy behaviour.

Correction: report baseline and compressed results on the same hardware and held-out slices — accuracy, p95 latency, memory.

The tell: a compression table with size and no latency, or accuracy measured on the calibration set used to choose ranges. One aggregate score with no per-slice check is the second tell.

Retrieval check— compression

  1. Weights span [−2, 2]. What is the symmetric INT8 scale and the maximum rounding error?
    Answer

    s = 2 / 127 = 0.01575; the error is at most 0.00787 per weight.

  2. Why does per-channel quantization usually beat per-tensor?
    Answer

    One large outlier channel no longer sets the scale for every other channel, so ordinary weights keep more distinct codes.

  3. What does raising the distillation temperature do to the teacher's targets?
    Answer

    It softens the distribution: the top class loses mass, near-miss classes gain it, exposing similarity hard labels hide.

Solve it · 059 — Symmetric INT8 quantization

Build it in Colab— compression

Runnable, NumPy-only, no setup: open the notebook in Colab · local copy. Add an outlier weight and watch every other error grow.

import numpy as np
w = np.array([-0.9, -0.3, 0.0, 0.45, 1.2])       # one tensor
s = np.abs(w).max() / 127                         # symmetric scale
q = np.clip(np.round(w / s), -127, 127)           # integer codes
w_hat = q * s                                     # restored weights
print("scale", round(s, 5), "max error", round(np.abs(w - w_hat).max(), 5))
