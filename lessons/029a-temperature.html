Inference, one symbol at a time · Lab 1

softmax(z/T) — temperature

You can compute next-token probabilities at three temperatures, and say precisely what the dial does and does not change.

Where this sits

p = softmax( z / T )

Lab 1 · z is the logit vector; T is the temperature

The model's last layer produces one raw score per vocabulary item. That score is called a logit: any real number, positive or negative. Softmax turns the row into probabilities, and the sampler draws one token from them.

One dial before sampling

Temperature divides every logit by the same number before softmax. T = 1 leaves the model exactly as trained. T below 1 sharpens the row; T above 1 flattens it. No weight changes, no extra computation worth counting — the logits are simply rescaled first.

TScaled logitsWeights
0.5[4, 2, 0]0.867 / 0.117 / 0.016
1[2, 1, 0]0.665 / 0.245 / 0.090
2[1, 0.5, 0]0.506 / 0.307 / 0.186

Dividing is raising to a power

Dividing logits by T is the same as raising each probability to the power 1/T and renormalising. At T = 0.5 that means squaring: 0.665² = 0.442, 0.245² = 0.060, 0.090² = 0.008. The total is 0.510, so the new shares are 0.867, 0.118, 0.016. Squaring punishes small numbers, so the leader gains.

At T = 2 the same arithmetic takes square roots: 0.816, 0.495, 0.300, total 1.611, giving 0.506, 0.307 and 0.186.

The two limits

As T falls toward 0, the largest logit takes everything: with [2, 1, 0] at T = 0.1 the leader already holds 0.9999. As T rises, the row tends toward uniform 1/V. T = 0 cannot be computed — it divides by zero — so serving stacks special-case it as greedy pick-the-argmax.

What the dial is for

Near T = 1 the model samples in proportion to its trained distribution, which is what most chat products want. Lower values suit extraction and code, where one answer is right and variety is noise. Higher values suit brainstorming, where surprise is the point. None of these settings is more truthful; they trade repetition against variety.

Check the last row

e2 = 7.389 against 1, total 8.389, so the weights are 0.881 and 0.119. The gap doubled from 1 to 2, and the leader's share rose from 73% to 88%.

The trap

Most common wrong mental model

"Temperature 0 makes the model deterministic and more accurate." It makes decoding greedy: the same prompt on the same hardware usually gives the same text. It does not make the answer right, and batching or floating-point order can still change a near-tie.

Correction: temperature changes the distribution, never the ranking. Low temperature hides uncertainty rather than removing it, and it cannot add knowledge the weights do not hold.

The tell: set T = 0.2 and sample a thousand times. The rare token still appears; it has simply become rare enough to look impossible. If a test depends on that, the test is flaky, not the model.

Retrieval check

  1. Both logits are 0. What does T = 2 change?
    Answer

    Nothing. Zero divided by any positive T is still zero, so the row stays 0.5 / 0.5. Temperature can only widen or narrow an existing gap.

  2. With logits [2, 1, 0], what happens to the smallest weight as T rises from 1 to 2?
    Answer

    It rises from 0.090 to 0.186, more than double. Flattening helps the unlikely tokens most, which is why high temperature produces stranger continuations.
