lstm_cell_update should return the new LSTM cell state:

c_new = f * c_prev + i * g

The current implementation is wrong. Fix it without changing the signature.

  • f and i are gates in [0, 1]; raise ValueError when either is outside that range
  • g is any real candidate value
  • return a float

The additive path, not the multiplied one, is what lets the state survive many steps.

The contract

def lstm_cell_update(c_prev, f, i, g):

Starter

def lstm_cell_update(c_prev, f, i, g):
    """Return the new cell state f * c_prev + i * g."""
    return f * c_prev * i * g   # BUG: the update should add the write term
